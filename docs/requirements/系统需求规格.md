## 1. 系统描述

> 本章编号：`SYS-01`–`SYS-25`；文档闭环相关条目见第 7 篇。

本部分定义产品边界、交付线、页面分层、服务接口和适用于全部业务域的不变量。后续所有业务规则都必须与这里的边界一致。

### 目标

`SYS-01` 系统必须服务于空间认知、投影理解和几何构造过程的可视化，不以制造、参数化建模或工程出图作为产品目标。

`SYS-02` 系统必须在微信小程序、学生端云函数、教师端云函数和教师网页之间保持明确职责边界，任何一层不得通过隐式全局状态代替正式接口。

`SYS-03` 功能正确性、几何可解释性和教学反馈优先于功能数量；不能用视觉效果代替几何真值。

### 交付线

| 交付线 | 当前职责 | 运行形态 |
| --- | --- | --- |
| 微信小程序 | 学生互动学习、登录注册、投影体系、AI 教师、问卷、协议 | 原生 WXML/WXSS/JavaScript，Canvas 2D |
| 学生端云函数 `api` | 学生身份、学习记录、问卷、AI 教师、名册准入 | 微信云函数 |
| 教师端云函数 `teacher` | 教师登录、角色权限、名册、班级、学情、数据治理 | 微信云函数 |
| 教师网页 `teacher-web/` | 教师后台交互界面 | 原生 HTML/CSS/JavaScript，HTTP 网关 |
| 浏览器演示 `web/` | 可直接运行的几何教学演示 | 原生页面，复用 `pages/index/` 模块 |

`SYS-04` 学生端与教师端云函数必须保持独立部署和独立鉴权；不得把教师 token、学生 openid 或两套权限模型混用。

`SYS-05` 浏览器演示不得成为第二套几何实现；投影、截面和绘图逻辑应从 `pages/index/` 复用。浏览器选项与共享 Page 模式之间的索引差异必须由适配层显式映射，不能把 DOM 值直接当作内部索引。

### 小程序页面架构

当前注册页面以 `app.json` 为准：

| 页面 | 职责 | 登录要求 |
| --- | --- | --- |
| `pages/login` | 微信身份入口 | 否 |
| `pages/register` | 学校、姓名、学号资料维护 | 登录后 |
| `pages/index` | 点、线、面、基本立体、平面切割立体 | 是 |
| `pages/projection` | 三投影面体系与投影面展开 | 是 |
| `pages/ai` | AI 教师对话与拍照提问 | 是 |
| `pages/survey` | 学习效果问卷 | 是 |
| `pages/terms` | 用户协议与隐私政策 | 否 |

`SYS-06` `pages/video` 当前未注册且不进入小程序包；源码存在不等于当前功能可用，AI 教师也不得提供播放入口。研究资料、设计文档、开发脚本、网页后台和离线依赖等非运行文件必须与运行目录分离；软著、论文和专利材料存放在仓库外，并通过 `.gitignore` 与 `packOptions.ignore` 双重排除，禁止进入 Git、GitHub 或小程序源码包。

`SYS-07` 新增页面必须同时更新页面文件、`app.json`、相关接口和回归清单；不得只完成入口链接。

### 学生端几何分层

`pages/index/` 按以下职责组织：

| 层 | 代表模块 | 约束 |
| --- | --- | --- |
| 常量与预设 | `constants.js`、`presets.js` | 坐标、容差和教学预设集中定义 |
| 数学与投影 | `math-utils.js`、`projection.js` | 只做纯计算，不依赖 DOM 或 Canvas 状态 |
| 几何真值 | `section-geometry.js`、`basic-solid.js`、`section-math.js` | 输出几何数据，不承担 UI 反馈 |
| 绘制 | `draw-helpers.js`、`render-scene.js`、`section-render.js`、`solid-projection.js` | 只读取领域数据，不成为几何真值来源 |
| 交互 | `touch.js`、`ui-handlers.js` | 输入校验、状态更新与重绘调度 |
| 页面装配 | `index.js` | 页面 data、生命周期和模块组合 |

`SYS-08` 几何真值必须独立于渲染对象；三视图、空间视图和截面必须来自同一份领域数据。

`SYS-09` 渲染使用 Canvas 2D，不引入 Three.js、WebGL、自由旋转相机、前端框架或构建链。

`SYS-10` 高频拖动只允许更新必要状态并按帧重绘；页面销毁时必须停止动画、解绑交互并释放画布引用。

### 服务与接口边界

学生端正式调用链：

```text
Page → utils/api.js → wx.cloud.callFunction('api') → cloudfunctions/api/index.js
```

教师端正式调用链：

```text
teacher-web/js/api.js → CloudBase HTTP 网关 → cloudfunctions/teacher/index.js
```

`SYS-11` 两个云函数通过 `action` 分发业务；旧客户端收到已下线的 action 时必须得到明确的 `ACTION_RETIRED`，不能只返回模糊的“未知操作”。

`SYS-12` 页面不得直接操作云数据库，不得持有服务端鉴权结论作为永久权限；最终判定在云函数执行。

`SYS-13` 新增或修改 action 时，必须同步核对调用方、服务端路由、离线用例和部署状态。

### 全局数据与教学约束

`SYS-14` 学生身份与教师名册是两条独立路径：学生可自填资料，名册只能由教师端维护。

`SYS-15` 未在名册中的用户仍可使用互动学习工具，但 AI 教师与问卷权益按身份域规则执行。

`SYS-16` `ai_messages` 是教师端统计依赖的既有结构；除非用户单独批准数据库变更，不得改变其字段语义。

`SYS-17` AI 知识库与 Prompt 是长期教学资产，修改必须说明教学理由并完成 AI 回归。

`SYS-18` 密钥、密码和 Token 只能来自 `process.env.*` 或云开发控制台，不进入代码、文档、注释或 Git。

### 变化控制

`SYS-19` 冻结模块只在用户明确要求且存在可复现缺陷或经批准的结构调整时修改；不得以“更清晰”为由直接重构。

`SYS-20` 影响数据库字段、权限模型、教学资产、部署链路或跨端协议的变更必须单独列出风险和回滚方式。

`SYS-21` 文档与代码不一致时，以当前代码为事实，并在交付说明中登记冲突；不得修改代码来迁就历史文档。

`SYS-22` 每次架构变化必须明确统一规格中受影响的章节，避免重新产生按时间累积的一次性需求文件。

### 验收边界

`SYS-23` 首页能够打开并绘制，点/线/面可切换和拖动，基本立体与切割立体可显示，登录/注册链路可完成，是任何学生端改动的最低回归线。

`SYS-24` 云函数代码修改后必须部署，教师网页修改后必须发布；只改本地源码不能宣称功能已生效。

`SYS-25` 本项目没有自动化测试框架和 CI；存在开发者只读检查与离线用例，但它们不替代模拟器、真机、浏览器和云控制台验证。

## 2. 身份与准入

> 本章编号：`IAM-01`–`IAM-31`。

身份与准入连接学生账号、教师名册、班级状态和功能权益。互动工具保持开放，AI 与问卷权益再由服务端实时判定。

### 身份来源

`IAM-01` 学生身份由微信 `openid` 锚定；`users` 保存登录身份、学校、姓名、学号和资料完成状态。

`IAM-02` 教师名册由 `students` 保存，只有教师端可以创建、导入、修改和删除。学生端注册只能写 `users`，不得申请、生成或修改名册。

`IAM-03` 教师账号由 `teachers` 保存，经账号密码换取 24 小时 token；教师身份只属于教师 Web 后台，不新增“教师学生”用户类型。

`IAM-04` 老师本人使用小程序时属于内部测试用户，与学生业务角色分开处理。

### 名册匹配

名册匹配键固定为“规范化学号 + 规范化姓名”，学校不参与匹配。

规范化规则：

- 学号：去首尾空白、去内部空白、全角转半角，保留大小写差异。
- 姓名：去首尾空白、将连续空白压缩为一个空格、全角字符转半角。
- 两项必须同时一致；禁止只按学号放行。

`IAM-05` 录入、导入、编辑和收编必须按同一匹配键判重，并返回明确冲突。

`IAM-06` 学生每次请求 AI 或问卷权益时都从当前 `users`、`students`、`classes` 实时判定，不缓存上一次放行结果。

`IAM-07` 名册按键查询的单次上限为 2000 条；超过上限时必须明确治理，不得静默漏人。

### 用户状态

非测试账号的状态如下：

| 状态 | 判定 | 互动工具 | AI 教师 | 问卷 |
| --- | --- | --- | --- | --- |
| 未登录 | 本地无登录用户 | 不可用，先登录 | 不可用 | 不可用 |
| 未注册游客 | 已登录，姓名或学号缺失 | 可用 | 不可用 `no_profile` | 不可用 |
| 已注册游客 | 资料完整，名册未命中 | 可用 | 不可用 `not_in_roster` | 不可用 |
| 在班学生 | 名册命中且班级 `active` | 可用 | 可用 `ok` | 可用 |
| 停用班学生 | 名册命中但班级非 `active` | 可用 | 不可用 `class_archived` | 可用 |
| 未分班学生 | 名册命中但 `class_id` 为空 | 可用 | 不可用 `no_class` | 可用 |

`IAM-08` 身份查询接口保留名称 `roster.status`，但其当前语义是统一身份/准入状态查询，不是旧白名单查询。

`IAM-09` 读名册或班级失败时必须 fail closed，返回可重试的 `check_failed`，不得误报为“不在名册”或直接放行。

### 测试账号

`IAM-10` 测试账号包括两类：

- `INTERNAL_OPENIDS` 环境变量中命中的内部账号；
- `users.data_quality = 'test'` 且由超级管理员标记的账号。

`IAM-11` 测试账号全功能开放，不受名册、班级和资料完整度门槛限制；接口回传 `test_account=true`、`bypass=internal|test`，前端明确提示“不计入真实学情”。

`IAM-12` `is_internal` 只由环境变量决定，登录时强制覆盖写，禁止人工直接修改。

`IAM-13` `data_quality` 可取 `production`、`test`、`unknown`；`data_quality_source` 可取 `auto`、`manual`。人工标记不得被自动回填覆盖。

`IAM-14` 只有超级管理员可以修改 `data_quality`；学生端注册/登录忽略客户端提交的测试身份字段。

### 学生端鉴权流程

```text
读取当前用户
  → 测试账号？是：student / ok，跳过名册与班级门槛
  → 姓名或学号缺失？是：guest / no_profile
  → 按键查询名册并比对姓名
      失败：guest / check_failed
      未命中：guest / not_in_roster
  → 名册命中但无 class_id：guest / no_class
  → 读取班级失败：guest / check_failed
  → 班级不存在：guest / no_class
  → 班级状态非 active：guest / class_archived
  → 其余：student / ok
```

`IAM-15` `resolveAccess` 是学生端 AI 与问卷权益的唯一判定入口；不得在页面或其它云函数中复制一套简化放行逻辑。

`IAM-16` AI 拒绝码与原因保持一一对应：

| 原因 | 错误码 |
| --- | --- |
| `no_profile` | `NO_PROFILE` |
| `not_in_roster` | `NOT_IN_ROSTER` |
| `class_archived` | `CLASS_ARCHIVED` |
| `no_class` | `NO_CLASS` |
| `check_failed` | `ACCESS_CHECK_FAILED` |

`IAM-17` 问卷权益使用 `in_roster` 或测试账号放行，不使用 AI 的班级 `active` 条件；因此停用班学生仍可提交问卷。

`IAM-18` 会话开始与行为事件必须写入当时的 `access_level`、`access_reason`、`in_roster`、`is_internal` 和 `access_test_account` 快照。

### 教师与超级管理员权限

| 能力 | 普通教师 | 超级管理员 |
| --- | --- | --- |
| 查看班级/名册/学情 | 仅本人负责范围 | 全局只读 |
| 新建、编辑、停用本人班级 | 是 | 否，恢复已停用班除外 |
| 增删本人班级成员 | 是 | 否 |
| 录入、导入、编辑、删除本人名册 | 是 | 否 |
| 新增/删除本人给名册学生的备注 | 是 | 否 |
| 查看未入册用户 | 否 | 是 |
| 收编到自己负责的班 | 是，手动输入学号+姓名 | 可从未入册列表指定班收编 |
| 管理教师账号 | 否 | 是 |
| 标记演示班 | 否 | 是 |
| 标记/回填数据质量 | 否 | 是 |
| 按人合规清理 | 否 | 是 |

`IAM-19` 权限必须在 `teacher` 云函数校验；前端隐藏按钮只用于减少误操作，不是安全边界。

`IAM-20` 超级管理员不得代改教师名册、备注或成员；唯一业务写例外是“恢复他人已停用班级”，且只改班级状态。

`IAM-21` 停用教师前必须确认其名下没有活动班级；负责人已停用或缺失时不得恢复班级。

`IAM-22` 本期不支持跨教师转班或班级移交；跨教师收编必须返回明确冲突，不得生成重复名册行。

### 登录与隐私

`IAM-23` 本地 `hfjh_user` 只用于减少重复登录操作；真正身份、名册和班级状态由云函数重新确认。

`IAM-24` 首页、AI 页、问卷页无本地用户时跳转登录页；协议页允许匿名。

`IAM-25` 拍照提问必须先通过微信隐私授权，同意按钮使用 `open-type="agreePrivacyAuthorization"`；拒绝授权不影响文字提问和互动工具。

### 验收

`IAM-26` 对未注册游客、已注册游客、在班学生、停用班学生、未分班学生各调用一次 AI，返回码必须与第 3 节一致。

`IAM-27` 测试账号在无资料、未入册、未分班或班级停用时仍可提问和提交问卷，且报表将其归入测试线。

`IAM-28` 修改名册学号/姓名后，下一次 AI 请求应立即按新键重新判定，不依赖前端缓存。

`IAM-29` 班级停用后只关闭 AI，互动与问卷保持可用；恢复班级后 AI 资格自动恢复。

`IAM-30` 普通教师访问他人班级或名册写接口返回 403；超级管理员对教师业务数据写操作返回 403，只读查询正常。

`IAM-31` 名册判重、学号全角转半角、姓名空白压缩和大小写敏感均应通过离线用例。

## 3. 学生学习

> 本章编号：`STU-01`–`STU-41`。

本部分以学生的学习闭环组织功能：观察空间对象、操作几何、读取投影、形成学习记录，并在满足条件时提交问卷。

### 学习主线

学生端的核心学习闭环是：

```text
登录
  → 在空间中观察点/线/面或立体
  → 调整类型、位置、姿态或截平面
  → 同时观察空间视图与第一角三视图
  → 通过投射连线、对应关系或投影展开理解二维与三维的映射
  → 产生可统计的学习会话与行为记录
```

`STU-01` 任一教学模块必须同时提供“对象当前状态”和“为何这样投影/截切”的可见反馈，不能只展示最终图形。

`STU-02` 教学坐标统一位于第一分角，默认范围为 `0–8`；界面显示度数时内部角度仍使用弧度。

`STU-03` 用户操作后应立即得到反馈，结束拖动时必须保存最终精确结果，不得把预览近似值当成最终几何真值。

### 点、线与面

`STU-04` 点模块必须支持一般点、原点、三个投影面和三条坐标轴预设，并允许在展开投影图中拖动投影点。

`STU-05` 拖动一个投影点后，空间点与其余两个投影必须同步，投影对应关系不得错位。

`STU-06` 直线模块必须支持一般线、水平线、正平线、侧平线和三类投射线，并能从三视图端点同步改变空间直线。

`STU-07` 平面模块必须支持一般位置和专业位置平面预设；空间平面与三个投影必须使用同一组 A、B、C 顶点数据。

`STU-08` 点、线、面模式切换时，当前模式交互状态、页面滚动锁定和导航标题必须同步复位或更新。

### 基本立体与平面切割

`STU-09` 基本立体支持棱柱、棱锥、圆柱、圆锥、圆球和圆环六类，并提供当前类型适用的尺寸参数。

`STU-10` 立体参数、旋转和平移必须共同决定空间几何；三视图只能读取这些参数和计算结果，不能维护第二份几何状态。

`STU-11` 旋转轴和平移轴使用明确状态；重置只影响当前立体，并恢复该立体的默认参数、姿态和轴状态。

`STU-12` 平面切割模式支持水平面、正垂面和侧平面，并支持角度与偏移连续调整。

`STU-13` 截交结果必须由几何真值层生成，空间截交线与三视图截交投影必须来自同一结果。

`STU-14` 截平面完全离开立体、相切、过顶点或与表面共面等退化情形必须返回稳定结果，不得继续传播 `NaN` 或造成整帧停止绘制。

`STU-15` 曲面体拖动期间必须遵守既有节流与缓存策略；不得以架构整理为名改变已验收的跟随性和滚动锁定时序。

### 投影体系页面

`STU-16` 投影体系页面必须展示互相垂直的 V/H/W 三投影面、空间点 A 与三个投影 a、a′、a″。

`STU-17` 页面必须支持“第一分角”和“八分角”两种投影面范围；两种范围只改变板面与坐标轴显示范围，不改变空间点真值。

`STU-18` “投影展开”必须让 H 面绕 OX、W 面绕 OZ 旋转至 90°，展开结果与下方第一角三视图逐点一致。

`STU-19` 展开角应可连续观察，动画期间按既有节流同步界面，不得每帧调用 `setData`。

`STU-20` 空间视图左右拖动只改变观察方位，不得改变几何真值、三视图或已展开的结果。

### 页面与导航

`STU-21` 首页、AI 页和问卷页必须先登录；协议页允许匿名访问。

`STU-22` 未填写完整资料的已登录用户仍可使用全部互动几何工具。

`STU-23` 页面在手机竖屏、平板横屏和宽屏下必须保持可操作；宽屏使用左右布局时不得挤压投影图或参数面板。

`STU-24` 拖动画布期间不得同时滚动页面；触摸取消或页面隐藏时必须结束拖动状态。

### 学习会话与行为记录

`STU-25` 进入学习页面后开始会话，离开页面结束会话；会话必须记录模块、开始时间、结束时间、持续时长、交互次数和身份状态快照。

`STU-26` 会话有效判定保持为“持续至少 60 秒或交互至少 3 次”；未正常结束的会话不得被统计为有效会话。

`STU-27` 章节进入/退出、AI 提问、登录/退出和互动工具等行为可写入 `learning_records`，用于教师端学习轨迹和章节进度。

`STU-28` 行为记录包含姓名/学号快照与身份快照；快照在写入后不随后续改名、改班或标记变化自动回填。

`STU-29` 埋点失败不得阻塞几何交互、AI 回答或页面退出。

### 学习效果问卷

`STU-30` 问卷包含互动工具帮助程度、空间理解程度、AI 教师使用频率和帮助程度、开放建议与学习方式多选。

`STU-31` Q1、Q2、Q3 为必答；Q3 选择“从没使用”时 Q4 自动跳过；其余字段可选。

`STU-32` 问卷邀请与提交权限由服务端判定：名册命中的学生及测试账号可用；班级已停用但名册仍命中的学生仍可提交。

`STU-33` 同一账号对同一问卷只允许提交一次；前端提交按钮状态不能替代服务端重复提交校验。

`STU-34` 有效学习会话达到 5 次后可触发问卷邀请；后续提醒按既有增量规则执行，不得对已完成问卷重复邀请。

### 验收

`STU-35` 给定一般点、轴线和投影面上的点，切换预设并拖动任一投影，空间点与三个投影应同步且对应连线正确。

`STU-36` 给定任意直线和平面，应从三个投影视图拖动端点/顶点并得到同步空间结果。

`STU-37` 六类基本立体应分别验证参数调整、旋转、平移、旋转 90° 和重置。

`STU-38` 六类切割立体应分别验证水平、正垂和侧平截平面，并确认空间图与三视图同步。

`STU-39` 投影体系页应在 0°、中间角度和 90° 下验证展开结果，并与下方三视图逐点核对。

`STU-40` 手机竖屏、平板横屏和宽屏至少各验证一次布局、拖动与滚动锁定。

`STU-41` 问卷应覆盖正常提交、缺必答、Q4 跳过、重复提交和无权限提交。

## 4. AI 教师

> 本章编号：`AI-01`–`AI-42`。

AI 教师在既有的学生身份和课程内容边界内工作。检索、生成、图片识别和视频提示分别降级，回答主链不得因旁路故障中断。

AI 页面内部按职责拆分为：`ai.js` 负责页面装配与生命周期，`ai-access.js` 负责准入展示，
`ai-input.js` 负责文字与图片输入，`ai-privacy.js` 负责微信隐私授权，
`ai-conversation.js` 负责消息发送与回答呈现。拆分不改变 WXML 事件名或云函数接口。

### 目标与边界

`AI-01` AI 教师必须帮助学生理解知识点、分析题目和形成作图步骤，不替学生代写作业，不直接判定答案对错。

`AI-02` AI 教师回答以文字讲解为主体；配套视频只作为“参考观看”，不能替代文字步骤，也不能在工作区内提供播放入口。

`AI-03` AI 教师调用链保持为：

```text
pages/ai
  → api.ai.ask
  → 服务端准入
  → 课程检索服务（可降级）
  → 本仓库 Prompt + 16 篇知识库 + 检索片段
  → DeepSeek 文本生成或 Qwen-VL 图片读题
  → ai_messages 保存问答
  → ai_teaching_events 旁路记录推荐与观看事件
```

`AI-04` 新增独立 AI 云函数前必须证明不会复制鉴权、学生上下文和教学口径；当前唯一学生端入口是 `api`。

### 对话与上下文

`AI-05` 用户可发送纯文字、纯图片或文字加图片；两者至少存在一项，空消息必须拒绝。

`AI-06` 用户文字在服务端最多 2000 字，小程序输入框当前限制 300 字；超限应返回明确错误。

`AI-07` 同一对话的上下文最多读取最近 12 条消息；知识点优先使用本次显式值，其次按问题匹配，最后继承会话知识点。

`AI-08` 对话必须保存会话标题、知识点、用户消息、助手消息、模型与 token 用量（可用时）以及消息时间。

`AI-09` 同一 `openid` 只能读取自己的对话详情和消息；“新对话”只清空当前前端会话，不删除历史数据。

`AI-10` 单次发送必须防止重复提交；网络失败、准入拒绝或配额耗尽后必须恢复发送状态。

### 教学回答口径

`AI-11` 回答应短、正确、可执行，目标不超过一屏；先给出最关键结论或步骤，再给简短解释和下一步引导。

`AI-12` 回答不得使用前端无法渲染的 LaTeX；使用教材可读的几何符号和自然语言。

`AI-13` 不得编造标准号、公差数值、比例系数或教材页码；查表题只说明查什么、如何查。

`AI-14` 不得复述题目或题干识图结果，不得使用“根据题意”作为回答开头。

`AI-15` 回答必须区分画法几何与工程制图课程的术语和任务边界。

`AI-16` 知识库与 Prompt 变更必须经过教学正确性复核、知识点路由检查和 AI 对话回归。

### 检索与生成

`AI-17` 课程检索服务返回命中片段、知识点和参考视频信息；本仓库仍负责最终回答生成，避免教学口径分裂。

`AI-18` 检索片段每条正文最多 400 字、最多 4 条，并与知识库一起注入；总知识上下文受 `maxKnowledgeChars` 限制。

`AI-19` 检索服务超时、鉴权失败、返回格式错误或未命中课程知识时，必须降级到本地知识库 + DeepSeek；用户不得看到服务端技术错误。

`AI-20` 检索命中且无可用视频时仍应正常返回文字回答；不得出现“命中但没有答案”的状态。

### 图片提问

`AI-21` 图片提问用于让学生拍摄题目，不用于采集姓名、学号、人脸或其它个人信息；界面必须提示避免拍到个人信息。

`AI-22` 图片在客户端压缩后传输，服务端只在本次请求中使用，不得写入数据库、云存储或模型训练语料。

`AI-23` 普通账号每天最多 2 次图片提问；测试账号和内部账号不限次。

`AI-24` 图片配额以服务端 `learning_records` 中当天的 `ai_photo_ask` 事件为准，客户端计数不可作为放行依据。

`AI-25` 超过配额时不得调用视觉模型；返回 `IMAGE_QUOTA_EXCEEDED` 和剩余次数，并保留文字提问能力。

`AI-26` 服务端环境变量 `AI_IMAGE=off` 必须能紧急关闭图片通道；纯图片请求返回可理解提示，文字提问不受影响。

### 视频与教学事件

`AI-27` 检索结果中的视频定位按知识点相关性筛选，最多 3 条，按相关度降序。

`AI-28` 个人主体当前不允许教育视频播放，`VIDEO_PLAYBACK` 默认 `off`；前端只显示视频标题、时间点和“在学习通课程相应章节观看”的文字提示。

`AI-29` 不得在回答正文中承诺“点击播放”；重新开放播放入口必须先确认平台类目允许并完成审核。

`AI-30` `ai_teaching_events` 独立记录 `video_recommend`、`video_open`、`video_complete`；不得把播放事件写入 `learning_records`。

`AI-31` `video_recommend` 只能由服务端在推荐时写入；客户端只能上报 `video_open` 和 `video_complete`。

`AI-32` 教学事件写入失败不得影响 AI 回答；事件应带对话、消息、视频和知识点关联，并限制文本与时间值范围。

### 隐私、安全与配置

`AI-33` 禁止向检索服务发送学生姓名、学号、openid 或完整历史对话；只发送完成本次回答所需的匿名问题、图片和上下文。

`AI-34` 图片与题目内容不得长期留存于第三方服务；具体第三方条款须与隐私政策保持一致。

`AI-35` API Key、检索 token 和内部 openid 名单只配置在云函数环境变量中，不得进入小程序包或教师网页。

`AI-36` 图片提问、视频、检索服务和生成模型必须分别具备可关闭/降级路径；单个外部依赖故障不得使全部教学功能失效。

### 验收

`AI-37` 文本提问应覆盖知识点命中、追问继承、空消息、超长消息、网络失败和服务侧超时。

`AI-38` 图片提问应覆盖首次授权、拒绝授权、成功识别、模糊图片、配额用尽、测试账号不限次和 `AI_IMAGE=off`。

`AI-39` 检索命中、无视频、服务超时和返回格式异常四种路径都必须形成可读回答或明确可重试提示。

`AI-40` 检查回答中无 LaTeX、无编造数值、无题目复述，并确认文字步骤是答案主体。

`AI-41` 验证 `ai_messages` 既有字段未被教学事件修改，`ai_teaching_events` 事件字段完整且无越权伪造。

`AI-42` 修改 AI 云函数后必须重新部署；修改知识库或 Prompt 后必须重新部署并完成真实对话回归。

## 5. 教师工作台

> 本章编号：`TCH-01`–`TCH-50`。

教师工作台负责名册、班级、学情和治理。它通过独立鉴权管理业务数据，与学生端云函数保持边界，不共享教师 token 或学生身份判定。

教师云函数内部按稳定职责分工：`index.js` 只负责 action 处理器与路由；
`lib/runtime.js` 统一云开发、token、密码和分页查询；`lib/identity.js` 负责名册身份规范化；
`lib/class-model.js` 负责班级实体、归属校验和成员统计。领域模块只共享这一套身份与数据规则。

### 目标与信息架构

`TCH-01` 教师工作台面向两类管理身份：

- 普通教师：维护本人名册、班级和学生备注，查看本人范围学情。
- 超级管理员：维护教师账号、查看全局只读学情、管理未入册用户和测试数据标记。

`TCH-02` 后台导航按业务任务组织，而不是按开发阶段组织：

| 路由 | 业务职责 |
| --- | --- |
| `dashboard` | 教学驾驶舱、数据分线与班级概况 |
| `classes` | 班级列表、建班、停用与恢复 |
| `class-detail` | 班级信息、成员与历史名册归并 |
| `unrostered` | 未入册用户、身份筛选、收编与数据质量标记（仅超管） |
| `learning` | 学习行为记录，按可见范围过滤 |
| `ai` | AI 提问统计、知识点热点与问答明细 |
| `teachers` | 教师账号管理（仅超管） |
| `student-detail` | 学生档案、学习轨迹、AI 记录和教师备注 |
| `plp` | 点/线/面分析占位页 |
| `settings` | 当前账号信息与超管数据维护入口 |

`TCH-03` 导航可见性可以按角色收窄，但服务端必须再次执行权限校验。

### 名册

`TCH-04` 名册记录以 `students` 为唯一来源，字段包括学校、姓名、学号、班级关联和归属教师。

`TCH-05` 学号与姓名组合在全局名册中唯一；录入、导入、编辑和收编必须展示冲突明细。

`TCH-06` 普通教师只能维护 `owner_teacher_id` 等于本人的记录。

`TCH-07` 批量导入支持 CSV 文本、预览校验、忽略无效表头和逐条结果反馈；不得出现部分成功却无提示。

`TCH-08` 学生详情必须基于名册记录与学生注册账号的匹配结果展示；未注册名册学生显示零学习数据，而不是报错。

`TCH-09` 教师备注只对教师端可见，按名册记录关联；删除备注只能由创建备注的教师执行。

### 班级

`TCH-10` `classes` 是班级实体；`students.class_id` 是唯一权威归属，`students.class_name` 仅为展示和兼容快照。

`TCH-11` 班级包含名称、学校、状态、负责教师、备注、演示班标记和成员统计。

`TCH-12` 普通教师只能查看全部班级中的本人范围，只能编辑本人班级；超级管理员可以查看全部，但不得修改教师业务字段或成员。

`TCH-13` 同一负责教师下，“班级名 + 学校”在活动班级中唯一；不同教师可以拥有同名班级。

`TCH-14` 新建班级后成员数为 0；空班级是合法状态。

`TCH-15` 学生同一时间只能属于一个活动班级。加入其他活动班之前，必须先移出原班级。

`TCH-16` 添加或移出成员必须同时更新 `class_id` 和 `class_name`；成员范围限定为该班负责教师名册。

`TCH-17` 停用班级为软删除：学生记录、班级归属、学习数据和 AI 问答全部保留；停用期间禁止调整成员。

`TCH-18` 恢复班级前必须校验负责人账号在职，并确认没有同名同校活动班冲突。

`TCH-19` 超级管理员可以恢复任意已停用班级，但该操作只修改班级状态，不获得其它班级写权限。

`TCH-20` 未分班学生列表只返回调用者本人名册中的 `class_id` 为空记录，支持关键词筛选和批量归入班级。

`TCH-21` 从历史名册归并成员必须先 dry-run 展示数量与明细，提交时使用 `confirm_count` 防止数据变化后误写。

### 未入册用户与收编

`TCH-22` 未入册用户列表仅超级管理员可见，包含已注册未入册用户和未注册游客，支持按资料状态筛选。

`TCH-23` 普通教师只能按“学号 + 姓名”手动收编到本人负责的班级，不提供全校未入册列表。

`TCH-24` 超级管理员按账号收编时必须指定目标班级，名册记录归属写目标班负责教师，不得写超管本人。

`TCH-25` 目标班没有负责人、学生已在其他教师名下或班级已停用时，收编必须失败并返回可理解原因。

`TCH-26` 收编动作写入治理审计，不得通过重启或重复提交产生重复名册记录。

### 驾驶舱与学情

`TCH-27` 驾驶舱展示学生总数、在册学情、游客漏斗、测试数据、名册注册情况、近 7 天趋势、班级概况、学情提醒和 AI 热点。

`TCH-28` 普通教师只统计本人名册关联账号；超级管理员按全局只读范围统计。

`TCH-29` 教学驾驶舱、学习记录和 AI 分析默认只包含 `student` 线数据，必须显示被排除的测试、演示和游客数量。

`TCH-30` 学生详情展示累计时长、有效学习次数、AI 提问次数、事件数、章节进度、学习轨迹、AI 问答和教师备注。

`TCH-31` 学习记录按姓名/学号、班级和行为类型筛选，单个请求最多返回 500 条，默认 200 条。

`TCH-32` AI 分析展示今日、近 7 天、累计提问、知识点热点和问答明细；只能查看权限范围内学生。

`TCH-33` 数据分线优先级固定为 `internal > demo > test > guest > student`，每个用户唯一归属。

### 测试数据与治理

`TCH-34` 超级管理员可以为班级设置 `is_demo`，将整班从真实学情和班级统计中排除；该标记不影响鉴权。

`TCH-35` 超级管理员可以按人标记 `production`、`test`、`unknown`；人工标记优先于自动回填。

`TCH-36` 数据质量回填必须支持 dry-run、确认条数、可重复执行、审计留痕，并跳过人工标记。

`TCH-37` 运维型整表清理和批量物理删除保持下线；只保留按人的合规清理通道。

`TCH-38` 按人清理必须先预览统计；实际删除需明确确认人数和清理范围，其他人数据不得受影响。

`TCH-39` 治理动作、真实删除、教师停用、班级归档与数据标记必须可在 `maintenance_logs` 追溯。

### 教师账号

`TCH-40` 超级管理员可以创建、编辑、停用、启用和删除普通教师账号，并重置密码。

`TCH-41` 教师密码使用带随机盐的 scrypt 哈希；文档和前端不得保存明文密码。

`TCH-42` 停用、启用或重置教师状态后，应使相关 token 失效或在下一次鉴权时立即按最新教师状态拒绝。

`TCH-43` 超级管理员账号不能停用或删除；名下仍有活动班级的教师不能停用。

### 验收

`TCH-44` 普通教师与超管分别验证导航、列表范围和写接口 403/200 结果。

`TCH-45` 名册新增、编辑、删除、批量导入、冲突和备注增删必须覆盖成功与失败路径。

`TCH-46` 班级列表、详情、建班、重名、成员加入/移出、跨班冲突、停用、恢复和负责人停用约束必须覆盖。

`TCH-47` 未分班调整、历史名册归并、未入册筛选与超管收编必须验证范围和审计结果。

`TCH-48` 驾驶舱三线、学生学习记录和 AI 分析必须与同一统计口径一致，并验证教师范围过滤。

`TCH-49` 数据标记、回填、演示班、按人清理必须验证 dry-run、确认、幂等与权限。

`TCH-50` 教师网页修改后必须发布预览仓；云函数修改后必须部署，两者都完成才算生效。

## 6. 数据、质量与交付

> 本章编号：`DATA-01`–`DATA-40`。

本部分把前述业务流程收敛到数据权威、快照、统计口径、接口、验证和部署。其他部分引用这里的字段与门禁，不另行定义第二套口径。

### 数据权威

`DATA-01` 身份、名册、班级、学习、AI 与治理数据必须由对应云函数写入；前端不得直接读写云数据库。

`DATA-02` 同一事实只能有一个权威来源：

| 事实 | 权威来源 |
| --- | --- |
| 学生登录身份与自填资料 | `users` |
| 教师名册与班级归属 | `students.class_id` |
| 班级状态、名称、学校与演示标记 | `classes` |
| 教师账号与会话 | `teachers`、`teacher_sessions` |
| 学习会话 | `learning_sessions` |
| 学习行为事件 | `learning_records` |
| AI 对话正文 | `ai_conversations`、`ai_messages` |
| AI 推荐与观看行为 | `ai_teaching_events` |
| 问卷邀请与作答 | `survey_invites`、`survey_responses` |
| 治理与删除审计 | `maintenance_logs` |

`DATA-03` `students.class_name` 是 `classes.name` 的兼容快照，只能用于展示；归属统计必须以 `class_id` 为准。

`DATA-04` 姓名、学号、班级名等快照字段写入后不会因源数据变化自动回填；涉及历史一致性时必须显式迁移或提供 dry-run。

### 集合职责

| 集合 | 用途 | 当前状态 |
| --- | --- | --- |
| `users` | 微信账号、自填资料、数据质量与内部测试标记 | 活跃 |
| `students` | 教师名册 | 活跃 |
| `classes` | 班级实体 | 活跃 |
| `teachers` | 教师账号 | 活跃 |
| `teacher_sessions` | 教师 token 会话 | 活跃 |
| `teacher_notes` | 教师备注 | 活跃 |
| `learning_sessions` | 学习会话与有效时长 | 活跃 |
| `learning_records` | 学习行为事件与身份快照 | 活跃 |
| `ai_conversations` | AI 会话头 | 活跃 |
| `ai_messages` | AI 消息正文与反馈 | 活跃，结构受保护 |
| `ai_teaching_events` | 视频推荐/打开/完成事件 | 活跃，旁路数据 |
| `survey_invites` | 问卷邀请触发记录 | 活跃 |
| `survey_responses` | 问卷作答 | 活跃 |
| `maintenance_logs` | 治理与清理留痕 | 活跃 |
| `roster` | 旧 AI 白名单 | 已废弃，不再参与判定 |
| `schools` | 预留学校实体 | 空占位，不参与业务 |
| `teacher_classes` | 旧教师-班级关系 | 遗留，当前不参与班级归属 |

`DATA-05` 删除集合、改字段语义或新增数据库唯一索引前，必须核对代码、真实数据量和历史兼容路径。

`DATA-06` 当前唯一性主要由云函数业务判重保证：名册为“学号 + 姓名”，教师账号为用户名，班级为负责教师下的“班名 + 学校”；不得假设数据库已存在唯一索引。

### 快照与时间

`DATA-07` 会话和事件的身份快照记录写入当时的准入状态，不随后续班级、名册或测试标记变化而更新。

`DATA-08` 学习会话以 `duration >= 60` 或 `interaction_count >= 3` 判定有效；统计有效学习次数时必须过滤 `is_valid=true`。

`DATA-09` 时间字段统一保存 ISO 字符串或既有毫秒时间戳，不得在同一字段混用两种格式。

`DATA-10` 北京日期计算按 `UTC+8`，避免 T0、每日图片配额和近 7 天统计在 UTC 边界错位。

### 数据分线

`DATA-11` 报表使用五类用户线，每个用户唯一归属：

1. `internal`：openid 命中 `INTERNAL_OPENIDS`。
2. `demo`：名册命中的班级 `is_demo=true`。
3. `test`：`users.data_quality='test'`。
4. `guest`：名册未命中。
5. `student`：名册命中且不属于上述类别。

`DATA-12` 教学效果、班级学情和 AI 热点只统计 `student` 线；测试、演示和游客必须单独显示或明确排除。

`DATA-13` `internal`、`demo`、`test` 的排除只影响报表归属，不改变鉴权；测试账号仍可全功能使用。

`DATA-14` 数据分线求和必须等于纳入统计的用户总数，不得出现无归属用户。

`DATA-15` 教师范围过滤以 `owner_teacher_id` 和名册匹配建立 openid 集合；超管查看全局只读数据。

### AI 数据边界

`DATA-16` `ai_messages` 保存问答正文、角色、知识点、时间和可用模型用量；不得混入教学事件或视频观看记录。

`DATA-17` `ai_teaching_events` 只保存推荐与观看行为，不重复保存完整问答正文。

`DATA-18` 教学事件必须带 `openid`、学号快照（可用时）、对话 ID、消息 ID、视频 ID、知识点与时间。

`DATA-19` 客户端不可上报 `video_recommend`，也不可写入任意扩展字段；服务端只接收约定事件类型和受控字段。

`DATA-20` 图片提问不得落库；配额计数以 `learning_records.ai_photo_ask` 事件为准。

### 审计与删除

`DATA-21` 自动回填、人工标记、收编、教师状态变化、班级停用/恢复、合规删除都必须记录操作者和影响数量。

`DATA-22` 删除类操作默认先 dry-run，执行时必须校验确认数量，并在 `maintenance_logs` 留痕。

`DATA-23` 普通教师删除名册记录只影响本人名下记录；超级管理员不得代删教师业务数据。

`DATA-24` 按人合规清理是保留的唯一批量删除通道，范围必须明确区分行为数据、名册/备注与注册账号。

`DATA-25` 真实姓名、学号、openid、数据库导出和含个人信息的数据分析报告不得提交进 Git。

### 接口契约

`DATA-26` 学生端 `api` 当前正式 action 包括：

`login`、`register`、`roster.status`、`session.start`、`session.end`、`record.event`、`statistics`、`survey.submit`、`ai.ask`、`ai.list`、`ai.detail`、`ai.feedback`、`ai.teaching_event`。

`DATA-27` 教师端 `teacher` 当前正式 action 包括：

`login`、`logout`、`me`、`teacher.*`、`dashboard`、`student.*`、`note.*`、`learning.list`、`ai.questions`、`class.*`、`data.personList`、`data.personPurge`、`data.backfillQuality`、`data.markQuality`。

`DATA-28` `roster.import/list/remove/clear`、`roster.backfill`、`data.reset`、`data.legacyRoster`、`data.emptyAccounts`、`student.purge` 已下线；调用时返回 `ACTION_RETIRED`。

`DATA-29` 服务端错误必须返回稳定错误码和用户可读消息；前端按错误码显示具体原因，不展示堆栈、密钥或数据库细节。

### 质量门禁

`DATA-30` JavaScript 修改后至少执行 `node --check`；涉及全仓接线时执行 `node scripts/run-all.js`。

`DATA-31` 几何变化必须补充数值/拓扑不变量、模拟器或真机回归；渲染截图不能替代几何断言。

`DATA-32` 云函数变化必须重新部署，并在真实账号与云数据库上验证；本地离线桩通过不等于线上通过。

`DATA-33` 教师网页变化必须同步到预览仓库并更新静态资源版本号，完成浏览器登录态和权限回归。

`DATA-34` 涉及 AI 知识库、Prompt、模型或检索服务时，必须验证知识点路由、降级链路与回答口径。

`DATA-35` 涉及权限、名册、班级或数据分线时，必须同时验证正向、越权、空数据、重复操作和幂等路径。

### 跨域验收矩阵

| 变化域 | 最低验证 |
| --- | --- |
| 学生学习体验 | 首页、点线面、立体、切割、投影体系、布局与拖动 |
| 身份与准入 | 五类账号、测试账号、fail closed、名册修改即时生效 |
| AI 教师 | 文本、图片、配额、检索降级、教学事件、回答口径 |
| 教师工作台 | 普通教师/超管权限、名册、班级、驾驶舱、治理动作 |
| 数据模型 | 读写字段、快照、索引/上限、统计口径、导出检查 |
| 部署链路 | 小程序编译、云函数部署、教师网页发布 |

`DATA-36` 任一改动即使只影响一个域，也必须执行 `SYS-23` 的学生端最低回归；涉及云端时增加部署后验证。

### 当前限制

`DATA-37` “点线面分析”页目前是占位，原因是学生端尚未形成工具级使用事件。

`DATA-38` 当前没有数据库级唯一索引、没有自动化测试框架和 CI；可靠性与一致性依赖云函数校验、离线用例和人工验收。

`DATA-39` 跨校“学号 + 姓名”相同可能误匹配，学校不参与准入判定的已知风险尚未消除。

`DATA-40` 班级移交、跨教师转班、休学/退学状态、拆分云环境和学校组织树均不在当前范围。

## 7. 需求演进与文档闭环

> 本章编号：`SYS-26`–`SYS-36`。

`SYS-26` 当前需求只维护一个权威正文：`docs/requirements/系统需求规格.md`。`README.md` 只承担入口、状态和历史索引职责，不重复需求正文。

`SYS-27` 每次需求按以下闭环执行：

```text
需求澄清
  → 在统一规格中定位受影响章节
  → 修改代码与数据
  → 完成验证和部署检查
  → 将已确认的最终行为回写统一规格
  → 删除被替代的描述与重复表述
  → 检查全文章节、编号、链接和跨域一致性
```

`SYS-28` 涉及多个业务域时，不新增平行文档或按日期追加“补充说明”，而是在统一规格中同步修改相关章节，并用稳定需求编号表达跨域约束。

`SYS-29` 文档回写发生在功能行为已确认之后；测试未通过、部署未生效或真机未验收的临时状态不得写成稳定需求。

`SYS-30` 每次需求完成后必须检查“实现、配置、数据、验收、限制”五个方面是否都已进入统一规格；任何一项遗漏都视为变更未闭环。

`SYS-31` 修改需求时优先合并相近规则，删除重复和矛盾描述；不能为了保留历史讨论而让正文同时存在两种当前行为。

`SYS-32` 已实现但尚未部署、尚未发布或尚未真机验收的能力，必须在“当前限制”中明确状态，不能表述为线上已生效。

`SYS-33` 统一规格的域编号表示稳定职责，不表示提出顺序。新增条目追加到对应域末尾；废弃条目应删除正文，并在需要时由历史文档保留追溯信息。

`SYS-34` 历史 `REQ-xxx.md`、实施计划和测试报告只作为证据，不再扩写，也不能覆盖统一规格。历史记录中的个人信息不得迁入当前规格。

`SYS-35` 一次需求完成的判定包括：

1. 代码、配置或数据行为已按要求实现。
2. 验证边界、未覆盖项和部署状态已如实记录。
3. 统一规格已回写，重复和过期内容已清理。
4. 受影响需求编号、验收条目和非目标保持一致。
5. 需求、代码、部署与文档没有仍然存在的已知冲突。

`SYS-36` 每次需求完成后必须更新 `docs/test/系统测试用例.md`：新增或调整受影响用例、同步“覆盖需求”编号，并运行 `node scripts/test-case-coverage-check.cjs`。覆盖检查通过只表示映射完整，不表示用例已经执行。
