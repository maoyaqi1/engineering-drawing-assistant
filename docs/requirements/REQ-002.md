## 1. 需求背景

教师后台目前没有「班级」实体，班级只是学生名册记录上的一个自由文本字段，导致教师无法查看「某个班有哪些学生」，也无法正式地新建或停用一个班级。

现状（2026-09-11 代码核对，基准提交 `2438fa3`；行号为 `cloudfunctions/teacher/index.js` 与 `teacher-web/js/app.js` 的当前行）：

1. 班级的唯一落点是 `students.class_name` 字符串：写入点在新增（`teacher/index.js:764`）、编辑（`:645`）、收编（`:703`）、批量导入（`:828`），记录结构由 `buildRosterRecord`（`:477`）定义。
2. 代码中已声明 `classes`、`schools`、`teacher_classes` 三个集合并在初始化时建表（`teacher/index.js:11-19`、`:87`），但**全仓没有任何读写**；`teacher_classes` 仅在被删除教师时清理（`:299`）。也就是说「班级集合」名存实亡。
3. 所有班级维度的展示与筛选都建立在字符串之上：驾驶舱「班级概况」按 `class_name` 聚合（`teacher/index.js:367-389`，返回 `:434`）、学习记录班级筛选（`:1053`、`:1065`、`:1085`）、AI 分析条目的班级列（`:1143`）、学生管理筛选下拉（`:606`、`:615`）、未入册视图的候选班级（`:565`，REQ-001 引入）。
4. 教师端「班级」只能通过逐个学生的编辑弹窗间接修改（`app.js` 的 `openEditStudent`、`openAddStudent`，班级为纯文本框），没有列表、没有成员视图、没有状态。
5. REQ-001 已把「未入册学生 → 设置班级」改为从已有班级中选择，并把「新班级的产生入口」明确留在学生新增/编辑弹窗（`REQ-001.md` §3.10、§14 A6）。这让「班级从哪来、谁来管」的问题更加突出：**当前没有任何入口可以正式创建一个班级或停用一个班级**。
6. 副作用已被记录：同一班级的不同写法会把驾驶舱班级概况与学习记录筛选拆成多项（`REQ-001.md` §1）。

## 2. 用户目标

教师（普通教师）希望：

1. 打开教师后台就能看到「我带的班级」列表，并知道每个班有多少人、有多少人已注册。
2. 能新建一个班级，创建后立刻可以在列表里看到它。
3. 能打开某个班级，看到它的学生名单。
4. 能把名册里的学生加进某个班，也能把学生移出班级。
5. 能把不再使用的班级停用，停用后历史学习数据与 AI 记录仍然可查。

超级管理员希望：能看到全部教师的班级，用于了解整体情况。

以上均以「登录教师后台后能观察到的界面与数据结果」为判定标准，不以内部实现为判定依据。

## 3. 功能描述

本阶段范围严格限定为六项能力：**班级列表、新建班级、查看班级详情、添加学生、移出学生、停用班级**。

3.1 班级列表：新增「班级」页面，列出当前教师有权看到的班级，字段包括班级名、学校、成员数、已注册人数、状态、负责教师（超管视图）；默认只显示「进行中」（`active`）的班级。
3.2 新建班级：在班级页面「+ 新建班级」弹窗中填写班级名（必填）与学校（可选），保存后写入班级实体并立即出现在列表中。
3.3 班级名唯一性：同一位教师名下，`班级名 + 学校` 与既有「进行中」班级重复时拒绝创建并提示；不跨教师强制唯一（不同教师可以各自建立同名班级）。
3.4 查看班级详情：进入班级详情页，显示班级基本信息（名称、学校、负责教师、状态、成员数、创建时间）与该班学生名单（姓名、学号、学校、注册状态、最近登录）。
3.5 添加学生：在班级详情页通过「+ 添加学生」从**当前教师可见名册**中选择学生加入本班；已在本班的学生不出现在候选或不可重复选择。
3.6 单一班级归属：同一名学生的名册记录在同一时间只能属于一个「进行中」班级；要换班必须先移出原班级（本阶段不提供直接换班）。
3.7 加入班级的写入效果：该学生名册记录的班级关联指向本班，同时把班级名写入兼容字段（见 §19），使现有页面无需改动即可正确显示。
3.8 移出学生：把学生从班级中移出，学生记录本身**不删除**，班级关联与兼容字段清空，学生回到「未分班」状态。
3.9 停用班级：把班级状态置为「已停用」（归档，软删除）；**不删除学生、不删除学习数据与 AI 记录、不自动清空学生的班级关联**（见 §19、§22）。
3.10 停用后的可见性：停用的班级默认不出现在列表，可通过状态筛选查看；其详情页仍可打开（只读为主）。
3.11 与名册/AI 白名单严格隔离：班级操作**不改写** `roster` 集合，**不改变** AI 教师提问权限的开通与撤销时机；班级操作也不改变未入册/已入册状态。
3.12 未入册学生不可直接入班：只有已在该教师名册中的学生才能被加入班级；自主注册但未入册的学生必须先由超管收编（现有 `student.adopt`）。
3.13 空班级允许存在：新建后未加任何学生的班级是合法状态，界面显示空态提示而不是报错。
3.14 学生管理页保持兼容：本阶段不改动学生管理页的「班级」列显示、班级筛选口径，也不改动新增/编辑/收编弹窗的班级录入方式（延续 `REQ-001` §3.10、§14 A6 的结论）。
3.15 权限可见性：普通教师只能看到并管理自己创建的班级；超级管理员可以看到全部班级（对非本人创建的班级，本阶段的写操作范围见 §6 与 §13 U3）。
3.16 失败反馈：班级名缺失、重复，成员添加越权、成员不属于可见名册等情形，都在弹窗内就近显示错误文案，不整页报错、不静默失败。

## 4. 使用流程

### 4.1 新建班级并加入学生

1. 教师登录教师后台，左侧导航出现「班级」入口，默认落在班级列表页。
2. 列表显示「我带的班级」；无班级时显示空态与「+ 新建班级」引导。
3. 点击「+ 新建班级」，出现后台自有弹窗（复用现有弹窗组件），填写班级名（必填）与学校（可选）。
4. 点击「保存」：成功则弹窗关闭、列表出现新班级（成员数 0）；班级名重复或为空则在弹窗内显示错误，弹窗不关闭。
5. 点击列表中的班级名进入班级详情页，显示班级信息与「暂无学生」空态。
6. 点击「+ 添加学生」，弹窗列出当前可见名册中尚未加入本班的学生，可多选。
7. 点击「确定」：弹窗关闭，名单立即出现所选学生，列表页的成员数同步变化。
8. 返回班级列表，该班成员数已更新。

### 4.2 移出学生与停用班级

1. 进入某班级详情页，在目标学生行点击「移出班级」。
2. 出现确认弹窗；确认后该行从名单消失，成员数减少。
3. 到「学生」页面查看该生，班级列显示为「未分班」（与该生从未分班时一致）。
4. 回到班级列表，点击目标班级的「停用」。
5. 出现确认弹窗，文案说明「停用后班级不再出现在默认列表，学生与学习数据不会被删除」。
6. 确认后该班从默认列表消失；把状态筛选切到「已停用」可再次看到它，详情页仍可打开。

## 11. 验收标准

判定方式均为浏览器实操（Chrome）、云开发控制台或两者结合；本项目没有自动化测试与 CI，不得以「代码看起来对」代替实操。

1. [必须] 给定普通教师账号，当打开「班级」页面时，只列出由该教师创建的班级；判定方式：浏览器实操 + 控制台核对 `classes.owner_teacher_id`。
2. [必须] 给定超级管理员账号，当打开「班级」页面时，可看到全部教师的班级且能看到「负责教师」列；判定方式：浏览器实操。
3. [必须] 给定已登录教师，当新建一个班级并保存时，列表立即出现该班、成员数为 0、状态为「进行中」；判定方式：浏览器实操 + 控制台核对 `classes` 记录。
4. [必须] 给定同一教师下已存在「机械2401 / 安徽建筑大学」，当再次以相同名称与学校新建时，保存被拒绝并给出明确提示，弹窗不关闭；判定方式：浏览器实操。
5. [必须] 给定班级名为空，当点击保存时，就地提示必填并拒绝提交；判定方式：浏览器实操。
6. [必须] 给定一个班级，当打开详情页时，显示班级基本信息与该班学生名单；判定方式：浏览器实操。
7. [必须] 给定一个没有任何成员的班级，当打开详情页时，显示空态提示且不报错；判定方式：浏览器实操。
8. [必须] 给定班级详情页，当点击「添加学生」时，候选只包含当前教师可见名册中尚未加入本班的学生；判定方式：浏览器实操 + 与「学生」页面名册范围对比。
9. [必须] 给定已选学生，当确认添加时，该生进入本班名单、列表成员数 +1，且 `students.class_id` 与 `students.class_name` 同时更新；判定方式：浏览器实操 + 控制台核对 `students` 记录。
10. [必须] 给定某学生已在班级 A，当在班级 B 中尝试加入该生时，该生不可被重复加入（提示需先移出）；判定方式：浏览器实操。
11. [必须] 给定某班级中的学生，当执行「移出班级」并确认后，该生从名单消失、成员数 −1，学生记录仍存在，`class_id` 与 `class_name` 清空；判定方式：浏览器实操 + 控制台核对。
12. [必须] 给定刚被移出的学生，当打开「学生」页面时，其班级列显示「未分班」；判定方式：浏览器实操。
13. [必须] 给定一个班级，当执行「停用」并确认后，默认列表不再显示该班，切换到「已停用」筛选可看到；判定方式：浏览器实操。
14. [必须] 给定被停用的班级，其学生记录、学习记录与 AI 问答记录均未被删除，且停用前已入班学生的班级关联未被清空；判定方式：云开发控制台核对 `students` / `learning_records` / `ai_conversations` 记录数。
15. [必须] 给定任意班级操作（新建、加人、移人、停用），`roster` 集合的记录数与内容不变；判定方式：云开发控制台核对 `roster`。
16. [必须] 班级操作后，驾驶舱「班级概况」、学习记录班级筛选、AI 分析班级列、学生管理班级筛选的显示口径与数据保持可用且一致；判定方式：浏览器逐页实操。
17. [必须] 给定普通教师账号，当直接调用他人班级的详情/加人/移人/停用接口时，返回 403 且不产生任何写入；判定方式：浏览器控制台构造请求或由开发自测脚本验证（不可用前端隐藏代替）。
18. [必须] 给定学生账号或未登录状态，当调用任何 `class.*` 接口时，返回 401/403，不返回班级数据；判定方式：同上。
19. [必须] 给定一名已注册但未入册的学生，当尝试把他加入班级时，系统拒绝并提示需先收编入名册；判定方式：浏览器实操。
20. [必须] 回归：登录/退出、学生管理（名册/未入册两个视图、筛选、编辑保存、新增学生、批量导入校验与提交）、REQ-001 的「设置班级」下拉、驾驶舱、学习记录、AI 教师分析页面均正常；判定方式：浏览器实操。
21. [期望] 班级列表的成员数与已注册人数，与驾驶舱「班级概况」中同名班级的统计一致；判定方式：浏览器对比。
22. [期望] 班级列表排序稳定（按创建时间或名称），筛选与空态文案清晰；判定方式：浏览器实操。

1. 部署要求：必须先完成 `cloudfunctions/teacher` 的「云端安装依赖」部署，再把 `teacher-web/` 同步到预览仓库；**未部署不算验证**（`AGENTS.md` C8 第 10 条、C11 第 3 条）。

3. 必测场景：新建班级（成功、重名、空名）、详情空态、添加学生（单个 / 多个 / 已在其他班）、移出学生、停用班级、停用后列表与筛选、权限 403、401、未入册学生入班被拒、`roster` 不变。

5. 数据一致性检查：班级操作前后各核对一次 `students.class_id` / `class_name` 的成对关系与 `roster` 记录数（§11 第 9、14、15 条）。
6. 本项目没有自动化测试、测试框架与 CI，验证结论只能来自浏览器实操、云开发控制台核对，或由用户实机确认。

## 14. 本次采用的假设

以下为记录人按用户本轮指示与代码事实采用的默认假设；与用户意图不符时以用户结论为准。

- A1 班级实体为独立集合 `classes`，成员关系不存放在班级文档的数组字段中。
- A2 `students.class_id` 是班级关联的唯一权威字段；`students.class_name` 保留为兼容展示快照，同一次写入中同步更新。
- A3 不新增 `class_members` 多对多集合；若将来出现「一名学生属多个教学班」的需求，再用关联集合扩展。
- A4 第一阶段只做六项能力：列表、新建、详情、添加学生、移出学生、停用班级。
- A5 不提供「编辑班级名」与「跨教师调班」，避免触发批量回写与归属变更。
- A6 停用为软删除，且不清空成员的班级关联。
- A7 普通教师只能管理自己创建的班级；超管可见全部（写权限见 U3）。
- A8 班级操作不写 `roster`，不改变 AI 白名单机制，也不改变 `student.create` / `student.adopt` / `student.delete` 的既有语义。
- A9 现有学生管理页保持兼容，继续使用 `class_name` 展示与筛选。
- A10 所有 `class.*` 的权限校验在云函数服务端完成。
- A11 不改动冻结模块 F1–F8，不在本轮部署。
- A12 本轮不创建 `docs/test/TEST-002.md`，测试文档在开发完成后由测试/审查 Agent 产出。

## 16. 数据模型（建议，实施需授权）

**班级实体 `classes`（新增集合；集合名在代码中已声明但从未使用）**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 系统 | 班级主键，被 `students.class_id` 引用 |
| `name` | string | 是 | 班级名，如「机械2401」 |
| `school` | string | 否 | 学校；参与唯一性判断（待 U4 确认） |
| `status` | string | 是 | `active`（进行中）/ `archived`（已停用），默认 `active` |
| `owner_teacher_id` | string | 是 | 负责教师（`teachers._id`），权限范围依据 |
| `owner_teacher_name` | string | 是 | 教师名快照，沿用 `students.owner_teacher_name` 的既有做法 |
| `created_at` / `updated_at` | string(ISO) | 是 | 与现有集合的时间字段格式保持一致 |
| `note` | string | 否 | 备注，第一阶段不在界面暴露 |

唯一性：同一 `owner_teacher_id` 下，`name + school` 不允许存在重复的 `active` 班级。
成员数：不落库为数组或计数字段，按 `students.class_id` 反查统计（范围有限，见 §10 R7）。

**学生侧关联（既有集合 `students`）**

- 新增 `class_id`（可为空）：唯一权威班级关联。
- 保留 `class_name`：兼容展示快照，与 `class_id` 同时写入/清空。
- 不新增、不重命名其他字段；`owner_teacher_id` 等既有字段语义不变。

## 17. API / action（建议）

沿用现有 `event.action` 分发与 `requireAuth` 模式，错误码沿用 `MISSING_*` / `NOT_FOUND` / `FORBIDDEN` / `DUPLICATE_*`（前端 `describeError` 已可识别）。网关无需改动（同一云函数内新增分支），但云函数必须重新部署。

| action | 入参 | 出参（要点） | 权限 |
| --- | --- | --- | --- |
| `class.list` | `keyword?`、`status?`、`owner_teacher_id?`（超管） | `items[]`（`id`、`name`、`school`、`status`、`member_count`、`registered_count`、`owner_teacher_name`、`created_at`）、`total`、`is_super` | 登录后；普通教师仅本人班级 |
| `class.create` | `name`、`school?` | 新建的班级对象 | 登录后 |
| `class.detail` | `class_id` | 班级对象 + `members[]`（`doc_id`、`name`、`student_no`、`school`、`registered`、`last_login_at`）+ `summary` | 同上（越权 403） |
| `class.members.add` | `class_id`、`doc_ids[]` | `{added}` | 同上；仅限本班可见范围与当前教师可见名册中的学生 |
| `class.members.remove` | `class_id`、`doc_ids[]` | `{removed}` | 同上 |
| `class.archive` | `class_id`、`archived: true` | `{ok}` | 同上（恢复入口是否开放见 U6） |

约定：

1. `class.members.add/remove` 只写 `students.class_id` 与 `students.class_name`，**不写 `roster`**，不调用也不改变 `student.create` / `student.adopt` / `student.delete`。
2. 所有写接口在服务端校验：班级存在、班级归属、成员属于当前教师可见名册、成员当前不属于其他 `active` 班级。
3. 单次批量上限与现有批量操作保持一致（避免一次请求过大）。

## 19. 数据兼容策略

1. **权威与快照分离**：`students.class_id` 是唯一权威班级关联；`students.class_name` 是展示快照。既有页面（驾驶舱班级概况、学习记录筛选、AI 分析、学生管理筛选）继续读 `class_name`，因此本阶段不需要改造它们。
2. **同写同清**：加入班级时同时写 `class_id` 与 `class_name`；移出班级时同时清空两者。任何一条路径都不得只写其中一者。
3. **未分班语义**：`class_id` 为空即「未分班」，与现状「班级列显示未分班」一致（`app.js` 列表渲染）。
4. **停用不回溯**：停用班级不清空成员关联，历史归属继续可见；若将来需要把停用班级成员统一转为「未分班」，属独立决策，不在本阶段。
5. **历史字符串不动**：既有 `class_name` 的不同写法保持原样，不由本阶段归并；由此产生的统计分裂属于已知遗留问题（§10 R8）。
6. **不做数据迁移**：本阶段上线不改写任何历史记录；新建班级只影响此后发生的写操作。
7. **回退友好**：只要 `class_name` 始终与 `class_id` 同步，即使代码回退到本阶段之前的版本，学生管理页与统计仍能正常工作。

## 20. 异常与边界情况

| 情形 | 期望行为 |
| --- | --- |
| 班级名为空/超长 | 服务端拒绝并返回可读错误；前端在弹窗内提示，不关闭弹窗 |
| 同教师下 `name + school` 重复 | 拒绝创建，提示已存在同名班级 |
| 班级不存在或已被删除 | 详情接口返回 404，前端提示并回到列表 |
| 成员已被移出后再次提交移出 | 幂等处理或提示「该学生已不在本班」，不报错崩溃 |
| 成员已属于其他 `active` 班级 | 拒绝加入并提示需先移出原班级 |
| 成员不在当前教师可见名册 | 服务端拒绝（403/400），不产生写入 |
| 未入册的自主注册学生 | 不进入候选；直接调用接口时被拒绝并提示需先收编 |
| 空班级 | 详情显示空态；列表成员数为 0 |
| 停用后再次停用 | 幂等，无副作用 |
| 停用班级的学生移出/加入 | 默认不允许对已停用班级做成员变更（提示先恢复或另建班级） |
| 网络失败或跨域被拦 | 沿用现有错误提示与网关引导文案（`api.js` 的 `NETWORK` 分支） |
| token 过期 | 前端清会话并回到登录页（现有行为，`api.js:19-49`） |
| 数据量较大 | 成员查询分批拉取，避免超出单次查询上限（§10 R7） |
| 双字段不一致的历史数据 | 详情页以 `class_id` 为准；不一致仅记录，不自动修复（可后续提供自查工具） |
