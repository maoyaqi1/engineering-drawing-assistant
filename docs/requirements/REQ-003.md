# REQ-003 数据模型与权限重构：Users / Students 双主数据 · 四态鉴权 · 测试数据治理

> 状态：**需求定稿（未实施）**。本文件只描述需求与约束，不含实现方案；实施涉及 C 级冻结模块，需另行授权。
> 决策来源：2026-09-13 用户方案《数据管理整体方案》+ 用户对 D1–D16 的逐条决策 + 2026-09-14 补充决策（读班失败 fail closed、登录拦截范围、上线门禁）。
> 核实基线：`cloudfunctions/api/index.js`、`cloudfunctions/teacher/index.js`、`pages/*`、`teacher-web/js/app.js`，以及 2026-09-13 云数据库导出快照（users 73 / students 156 / classes 3 / learning_sessions 134 / learning_records 299 / teachers 7）。

## 1. 需求背景（上一版的真实问题，均有证据）

1. **权限判定读副本**：AI 放行只读 `roster`（由名册派生）。副本被清空 → 全部用户失去 AI 权限，而名册完好（当前即此状态，`roster` 为空）。
2. **名册与已注册用户几乎没有交集**：名册 156 条中，两个新生班（各 75 人，学号 `2621…`）尚无一人注册；真正注册过的 21 个"零散使用者"都不在名册里。**2026-09-14 用户澄清：这不是名册数据错误——两个班是真实新生名单（先建班、后注册），零散使用者属于游客**（见 §19 数据归属裁定）。
3. **测试与生产同库无标记**：`users` 无来源/环境字段，`students.source` 恒为 `'teacher'`，只有一个云环境；AI 提问 6 次全部来自内部账号。
4. **超管权限过大**：9 处 `isSuper` 放行点可改/删他人名册、备注、班级；5 个 `data.*` 工具做物理删除（历史已执行 13 次 `personPurge`、1 次 `data.reset`、1 次旧白名单清理，累计删除 1205 会话 / 518 事件 / 320 AI 消息）。
5. **班级归属双轨**：`class_id` 权威、`class_name` 快照 → 出现"名册显示 5 人在教师组、班级成员只有 3 人"。
6. **驾驶舱口径混同**：全局统计（不分教师、不排除测试），无法区分在册学情与游客推广。

| D19 | **教师 = Web 上的管理者身份，不是学生端的用户类型**；同一位老师的微信在学生端就是**可标记的内部测试用户**（`is_internal`）。老师**允许建班、允许用自己的微信自测**；测试数据靠 `is_internal`（账号级）与 `is_demo`（班级级，演示班）从真实学情里剔除，**不引入"教师学生"这种混合用户类型** |

| D22 | **`is_internal` 只由 `INTERNAL_OPENIDS` 环境变量决定，人工不可改**；登录时强制覆盖写，不引入 `is_internal_source`（与 `data_quality_source` 机制刻意区分） |
| D23 | **本期不支持跨教师收编/转班**（全局唯一 + 无移交）。替代路径：由超管删除原记录后由目标教师/超管重新录入，或列入 2.0 的班级移交功能；验收需含对应负向用例 |

## 3. 术语与用户状态（统一定义）

| 状态 | 判定条件 | 互动 | AI 教师 | 服务端返回 |
| --- | --- | --- | --- | --- |
| 未登录 | 小程序本地无用户（`globalData.user` 为空） | ✗（先登录） | ✗ | 前端拦截，不调接口 |
| 未注册游客 | 已登录，未填齐姓名 + 学号 | ✓ | ✗ | `no_profile` |
| 已注册游客 | 已填姓名 + 学号，名册无命中 | ✓ | ✗ | `not_in_roster` |
| 已注册学生（在班） | 名册命中 **且** 该行班级为 `active` | ✓ | ✓ | `ok` |
| 已注册学生（班级停用） | 名册命中 **但** 班级为 `archived` | ✓ | ✗ | `class_archived` |
| 已注册学生（未分班） | 名册命中 **但** `class_id` 为空 | ✓ | ✗ | `no_class` |

术语约定：

- 「已注册」= 在 Users 里**填齐姓名 + 学号**（不等于入册）；
- 「入册」= 名册命中；
- 「未入册用户」= Users 中存在、名册未命中的人（含已注册游客与未注册游客）；
- **学校字段不参与任何资格判定**。

### 4.2 名册与班级

| 编号 | 需求 |
| --- | --- |
| R10 | 名册唯一键 = 全局「normalize(学号) + normalize(姓名)」；录入/导入前必须判重并列出冲突明细 |

## 7. 流程（目标态）

```text
未登录 → 打开小程序 → 必须先登录（index / ai / survey 均校验；terms 除外）
已登录 → 可用互动（未注册游客）
       → 填学校/姓名/学号 → 已注册游客 或 已注册学生
       → 已注册学生且班级 active 才可用 AI；班级停用 → class_archived；未分班 → no_class
教师   → 建班 → 录名册/导入 → 学生自动获得 AI 资格（无白名单动作）
       → 停用本班 → 该班学生失去 AI、保留互动；可自行恢复本班
超管   → 建教师账号 → 停教师前先把其名下班级全部停用
       → 查看未入册用户（含未注册游客）→ 收编到指定班（留痕）
       → 打标 / 回填 / 标演示班 / 归档 / 合规按人删除（留痕）
```

## 8. 报表口径（三条线）

| 分析目的 | 人群 | 自动排除 |
| --- | --- | --- |
| 教学效果 / 班级学情 / AI 热点 | 已注册学生（名册命中且班级 active） | 测试、演示班、游客 |
| 产品推广 / 转化漏斗 | 已注册游客 + 未注册游客 | internal 账号 |
| 数据治理 | 未入册用户列表、测试标记审计 | — |

5. **自动规则**（仅作初值，不替代人工）：姓名或学号为明显测试值（如 `1` / `无敌大野牛`）、学号非字母数字、T0 前且零行为的账号。
6. **回填任务**：幂等、可 dry-run、可重复执行；只改标记字段；执行写审计。
7. **人工修改**：`data_quality_source='manual'` 的记录，自动规则不得覆盖。
8. **不物理删除**：测试数据靠标记隔离，分析时排除。

## 13. 风险

1. 涉及 C 级冻结模块（F5、及首页 F1/F3/F4 的登录校验），需用户授权并跑冻结模块回归清单。
2. 历史打标无法 100% 准确：用户已逐条裁定归属（`is_internal 7` / `test 3` / 游客 63），但**未逐个核对的账号仍可能有误判**，需在回填后抽查。
3. 判定源改 `students` 后**资格完全由名册决定**：当前两个新生班尚未注册，而教师组会被 `is_demo` 排除、已注册的命中账号全部是 `is_internal`，因此**短期内在册学情为 0**（见 §12-7）；这是数据时序问题，不是缺陷，但会影响上线初期的报表观感与 AI 使用量。
4. `api` 云函数首次依赖 `classes`：读取失败已定 fail closed（R5），但会造成真实学生临时无法提问，需要监控与文案。
5. 物理删除下线后，垃圾数据只能靠标记隔离，未入册列表会持续变长。
6. 权限收窄与登录拦截改变现有操作路径，需回归验证。
7. **跨校同键误匹配**：匹配只用「学号+姓名」、学校不参与，且全局唯一只在**写入侧**防重。多校推广后可能出现"A 校与 B 校存在同姓名+同学号"→ 两边学生都能命中对方名册行。当前数据无此情况，属已知风险。
8. **`roster` 下线顺序不可颠倒**：旧版 `loadRosterSet()` 直读 `roster` 且无 try/catch（[api/index.js:110](G:/HFJH/cloudfunctions/api/index.js:110)）。必须按"先部署新代码 → 确认全仓零引用 → 最后删除集合"执行，否则线上学生提问会直接报 `SERVER_ERROR`。
9. **学号规范化规则变更的迁移风险**：现行实现只有 trim + 去空白（[teacher/index.js:446](G:/HFJH/cloudfunctions/teacher/index.js:446)、[api/index.js:95](G:/HFJH/cloudfunctions/api/index.js:95)），新增"全角转半角"后两端必须同时改，并确认**存量数据**（现网学号均为 ASCII，故当前无实际差异）。
10. **规模上限**：判定改为按键查询后，单次查询上限 2000（B6）；超过需分页或索引改造，否则会静默漏人。

## 14. 验收标准

1. 四态 + 四种原因：五类账号（未注册游客 / 已注册游客 / 在班学生 / 班级停用 / 未分班）各调一次 AI，返回码与 §3 表格一一对应。
2. 登录拦截：`index` / `ai` / `survey` 未登录时跳登录页；`terms` 可匿名访问。
3. 班级状态：停用后该班学生 AI 被拒（`class_archived`）、互动正常；恢复后 AI 恢复；教师可恢复本班、超管可恢复任何已停用班。
4. fail closed：人为令 `classes` 读取失败时，AI 返回可重试提示而非放行。
5. 名册唯一：同「学号+姓名」重复录入/导入被拦截并列出冲突。
6. 学号规范化：全角转半角生效、大小写敏感（`s2890658` 与 `S2890658` 不互相匹配，需人工核对）。
7. 停用教师：名下有 `active` 班级时被拒并列出清单；全部停用后成功；旧 token 立即 401。
8. 超管权限：对别班名册/备注/成员的写操作返回 403；收编、打标、归档、合规删除均写审计。
9. 未入册列表：包含未注册游客，可筛选；教师无权访问。
10. 报表：三条线互斥不漏，求和等于总用户数；教师驾驶舱仅含本范围。
11. 打标：新注册账号自动带 `data_quality` 与 `is_internal`；回填可重复执行且结果稳定；人工结果不被覆盖。
12. 快照：新增会话与事件均带 `access_level` / `access_reason` / `in_roster`，与当时状态一致。
13. 问卷：未注册游客与已注册游客既不会被邀请、也无法提交；已注册学生可提交。
14. `roster` 下线后：全仓无 `roster` 集合读写残留（文档同步更新），`roster.status` 仍可用且返回四态。
15. 演示班：`is_demo=true` 的班级不出现在班级概况、名册人数、按班活跃与班级维度学情报表中；两个正式教学班不受影响；即使老师微信漏配 `INTERNAL_OPENIDS`，该班仍被排除。
16. 归属闭合：`is_internal 7 + test 3 + 游客 63 = 73`，且四类互斥；`is_internal` 账号不出现于学情与游客两条线。
17. internal 豁免（D21）：`is_internal=true` 的账号在班级停用或未分班时仍能通过鉴权；非 internal 账号照常被 `class_archived` / `no_class` 拒绝。
18. 跨教师收编负向（D23）：某学生已在 A 教师名下时，B 教师收编返回明确冲突提示，且不产生重复名册行。
19. 恢复班级约束（B1）：负责人已停用时，恢复该班被拒绝并提示先启用教师。
20. 按键查询与上限（B6）：判定路径不再全表读 `students`；超过单次上限 2000 时有明确分页或提示，不得静默漏人。
21. `roster` 下线顺序（C1）：在测试环境演练"先部署新代码 → 确认零引用 → 再删集合"，确认旧代码不会读到已删除的集合。
22. `is_internal` 单一来源（D22）：人工无法修改 `is_internal`；更新 `INTERNAL_OPENIDS` 后重新登录即生效，抽查一致。
23. 鉴权排除回归（A1-补）：用 `500450 / 毛` 这类"internal 但不在名册"的测试号验证——改动其学号或姓名后提问被拒（`not_in_roster`），改回与名册一致则恢复；确认"内部账号也不能绕过名册命中"。
