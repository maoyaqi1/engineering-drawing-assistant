# 用户与鉴权模型（学生端 · 2026-09-13 定稿）

> 适用范围：小程序学生端（`pages/`、`utils/api.js`）与学生端云函数 `cloudfunctions/api`。
> 教师端只负责录入名册，不适用本文的放行判定。

## 角色

1. **正式学生**：微信登录 + 填写学校/姓名/学号，且「学号 + 姓名」与教师录入的名册一致。
2. **游客**：已登录但未填资料，或资料与名册不一致的学生。
3. **教师**（含超级管理员）：名册与班级的唯一录入端，见 `cloudfunctions/teacher`。

## 规则

1. **教师是名册唯一录入端**：只有教师端能创建/导入/修改/删除名册（`students` + `roster`）。学生端不得写名册、不得「申请入册」、不得自动入册；`register` 只写 `users`。
2. **匹配键恒为「学号 + 姓名」**：两端都做规范化（学号去空白、姓名 trim）；必须两项同时一致才放行，禁止只用学号（不同学校学号规则可能重复）。
3. **学校不参与放行**：学校字段仅用于展示与统计。
4. **游客保留基本功能**：点 / 线 / 面、基本立体、平面切割立体等全部互动教学功能与学习埋点（`session.start`、`session.end`、`record.event`、`statistics`）对游客正常开放。
5. **AI 教师提问属名册权益**：`ai.ask` 以及 `ai.list` / `ai.detail` / `ai.feedback` 必须在服务端校验，禁止只靠前端隐藏按钮。
6. **游客被拒时区分原因**：`reason = no_profile`（未填姓名学号，引导去完善资料）或 `not_in_roster`（已填但不在名册，提示需教师按「姓名 + 学号」录入，并回显当前资料便于核对）。
7. **服务端是权威**：名册被删除或改名后，学生端再次提问会被服务端重新校验并立即收回权限，不依赖前端缓存。

## 单一入口

学生端云函数 `cloudfunctions/api` 的 `resolveAccess(user)` 是唯一鉴权入口，返回
`{ level: 'student' | 'guest', reason: 'ok' | 'no_profile' | 'not_in_roster', in_roster }`；
`roster.status` 直接返回该结果（并回显 `name` / `student_id` / `profile_completed`），AI 相关 action 统一据此拒绝（`NO_PROFILE` / `NOT_IN_ROSTER`）。

离线用例见 `scripts/offline/run-access.cjs`（`node scripts/run-all.js` 会自动运行）。
