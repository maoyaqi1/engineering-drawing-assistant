# 版本冻结记录 v1.3.0

> 版本号：`v1.3.0`
> 冻结日期：2026-10-24
> 上一版本：`v1.2.0`
> 冻结范围：2026-10-24 工作区中属于工程制图学习助手开发和文档闭环的内容
> 冻结性质：源码与开发文档版本；不表示云函数已部署、小程序已上传或教师网页已发布

## 1. 版本定位

`v1.3.0` 是架构整理、需求文档统一和发布阻断修复版本。它不新增一套与现有系统并行的架构，而是按统一需求 `SYS / IAM / STU / AI / TCH / DATA` 的边界整理现有实现：

- 学生端继续使用原生微信小程序与 Canvas 2D；
- AI 页面从单文件装配拆为访问控制、输入、隐私、会话和页面入口；
- 教师云函数从单文件拆为运行时、身份、班级领域和 action 路由；
- 教学事件继续写入独立集合，不改变 `ai_messages` 与既有统计口径；
- 需求、测试用例和执行报告形成一条可追溯的文档链。

发布前重新执行：

```powershell
node scripts/run-all.js
```

结果：**29 项全部通过，0 失败**。其中：

- 几何真值回归通过；
- 截交三视图等价性 17/17 通过；
- 整体静态检查 11/11 通过；
- AI 页面结构、知识点路由和需求测试覆盖检查通过；
- 学生端与教师端全部离线云函数用例通过；
- 小程序预览包体已由 2743KB 降至 237.8KB，并能生成预览二维码；

需求与测试的详细证据见 `docs/test/TEST-20261024-需求基线全量验证.md`。该报告仍保留部分通过、未执行和阻塞项，本冻结记录不把离线检查扩大解释为完整业务验收。

因此，`v1.3.0` 表示 Git 源码和开发文档已冻结；云函数修改必须重新部署后才生效，教师网页必须同步发布后才对外生效。

## 6. 冻结约束

1. 后续修复应先从 `v1.3.0` 建立可追溯改动，不以“整理代码”为由重写冻结行为。
2. 修改 AI 页面分层、教师云函数领域模块或教学事件字段时，必须同时检查统一需求、测试用例、离线用例和迁移影响。
3. 修改 `ai_messages` 结构、教师权限范围或数据库字段前，必须单独报告影响面并取得用户确认。
4. 修改云函数后必须重新部署；修改教师网页后必须同步预览仓库；两者都不能以本地代码检查代替线上验证。
5. 后续版本继续维护单一需求正文和单一测试基线，不按每次需求新增平行规格。

## 7. 回滚边界

回滚源码可切换到上一版本标签：

```powershell
git -C G:\HFJH switch --detach v1.2.0
```

回滚源码标签不会自动回滚已部署云函数、数据库数据或教师网页预览环境。涉及线上状态时需要分别按部署记录处理。
