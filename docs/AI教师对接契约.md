## 1. 调用路径

```
小程序 pages/ai
   │ wx.cloud.callFunction({ name: 'api', action: 'ai.ask' })   ← 第一版不改
   ▼
云函数 api（学生端，已有）
   │  鉴权（resolveAccess）→ 会话历史 → 关键词粗定位 → 调千问服务 → 组装 Prompt → 生成 → 落库
   │ HTTPS + Bearer Token（服务端出网，不需要小程序域名白名单）
   ▼
千问侧 AI 教师服务（检索 + 生成）
```

要点：

1. **不新增云函数。** 学生端固定入口是 `api`（教师端为 `teacher`），`ai.ask` 的放行依赖 `cloudfunctions/api/index.js` 的 `resolveAccess`（名册 / 班级 / 演示班 / 内部账号 / 读库失败 fail-closed）。新增独立云函数会复制这套鉴权，产生两份权威。
2. **第一版小程序端零改动。** 前端只认识 `api` 的既定 action。
3. 云函数以服务端身份直连千问服务，与现有 DeepSeek、Qwen-VL 调用方式一致。

## 2. 接口定义

| 项 | 值 |
| --- | --- |
| 方法 / 路径 | `POST {QWEN_TEACHER_BASE_URL}/v1/ai-teacher/ask` |
| 认证 | `Authorization: Bearer ${QWEN_TEACHER_TOKEN}` |
| 请求头 | `Content-Type: application/json` |
| 超时约定 | 云函数侧 8 秒；超时即降级（见 §5） |
| 环境变量 | `QWEN_TEACHER_BASE_URL`、`QWEN_TEACHER_TOKEN` 只写在云函数环境变量里，**绝不入代码、文档、注释或 Git**（C5.4、C10） |

### 2.1 请求字段

| 字段 | 类型 | 必填 | 说明 | 现有代码对应 |
| --- | --- | --- | --- | --- |
| `question` | string | 是（仅有图片时可为空串） | 学生原话，最长 2000 字 | `event.message` |
| `conversation_id` | string \| null | 否 | 会话 ID，用于多轮 | `event.conversation_id` |
| `knowledge_point` | string \| null | 否 | 现有粗定位结果（`G01`–`G16`），可作为检索先验 | `matchKnowledgePoint()` |
| `history` | array | 否 | 最近 ≤12 条 `{ role, content }`，`role` ∈ `user` / `assistant` | `ai_messages` 最近 12 条 |
| `image_base64` | string \| null | 否 | `data:image/jpeg;base64,...` 或纯 base64。**2026-09-25 起启用**：学生拍题是主要用法；服务侧应先读题（抄出题干文字）再检索，`question` 可为空串 | `event.image_base64` |
| `top_k` | number | 否 | 期望返回切片数，默认 3 | 新增 |
| `threshold` | number | 否 | 相似度阈值，低于此值应返回 `matched=false` | 新增 |
| `client_request_id` | string | 否 | 云函数生成的请求 ID，仅用于双方排查对账 | 新增 |
| `generate` | boolean | 否 | 默认 `true`。**方案 C 下本仓库自己生成回答，会传 `false`**，服务侧可据此跳过自身的生成调用（省一次模型调用与延迟）；仍建议保留兜底生成能力 |

### 2.2 响应字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `answer` | string | 是 | 面向学生的回答，**≤150 字（一屏内）**，先结论后引导 |
| `matched` | boolean | 是 | 是否命中课程知识 |
| `video_refs` | array | 否 | 见 §3；无视频时返回 `[]` |
| `sources` | array | 否 | `[{ doc, kp_id, score, text }]`。**`text` 是命中片段正文（≤400 字/段，最多 4 段）**——方案 C 下本仓库用它 + 16 篇知识库一起生成回答；缺失时本仓库退回"仅用 16 篇知识库"生成 |
| `model` | string | 否 | 实际使用模型名，用于埋点 |
| `usage` | object | 否 | `{ prompt_tokens, completion_tokens, total_tokens }` |

### 2.3 命名与格式约定

1. 字段名统一 `snake_case`（与仓库现有 `conversation_id` / `knowledge_point` / `image_base64` 一致）。
2. 时间一律为**整数秒**；相似度分数为 `0–1` 的小数。
3. 响应必须是单个 JSON 对象，不包裹额外信封（`ok` 字段由云函数侧自行补）。

### 2.4 内容铁律（与现有教学口径一致）

1. **不得使用 LaTeX**（`$...$`、`\frac`、`\triangle` 等），显示端不渲染；用"三角形 ABC""∠ABC""⊥""∥"。
2. **不得编造**标准号、数值、比例系数、画法步骤；不确定就说明"不确定，建议核对教材/课件"。
3. 涉及查表（标准件尺寸、公差数值、模数系列等）时只教"怎么算、查哪页"，**不给表中数值**。
4. 不代写作业成品；不直接判定学生答案对错，先引导其讲出思路（教学信条见 `cloudfunctions/api/prompts/teacher_system_prompt.md`）。
5. **文字讲解才是答案主体**：回答必须是学生能直接照做的文字讲解（先结论或最关键一步，再一句解释，末了一句引导），**总长 ≤150 字**（一屏内）。视频只是"建议观看"的补充，不能替代文字讲解，也不能把回答写成"去看视频"。
6. **不得复述题目**：图片读题（题干转写）的结果**只用于检索**，不得出现在回答里；禁止"根据题意…""这道题要求…"这类把题干重念一遍的开头。
7. 只讲正确做法，不列易错点、不强调错误（与既有教学口径一致）。

## 3. `video_refs` 语义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `video_id` | string | 与知识库 `videoId` 一致，例：`xt_4求两交叉直线的公垂线` |
| `video_title` | string | 例：`4求两交叉直线的公垂线` |
| `kp_title` | string | 命中片段标题 |
| `start` | number | 片段起始秒 |
| `end` | number | 片段结束秒 |
| `time_label` | string | 例：`00:01 - 07:32`，前端可直接显示 |
| `score` | number | 该片段分数（0–1） |

规则：

1. **定位是"参考视频"，只要知识点相关即可**（2026-09-25 用户裁决）：**不要求是这道题的讲解**——学生问的题往往没有单独录制，检索到同一知识点/同一题型的讲解，就是合格的参考。要挡住的是**与知识点无关**的内容（"课程外"与"跑题"），不是"同知识点但不同题"。
   - 因此 `threshold`（0.55）即为按此口径校准的值：评测显示课程外 16 条全部正确拦截、同知识点内容正常通过，**暂不需要再提高**。
   - 也不需要在服务侧再加一次"这段视频讲的是不是这道题"的判定——向量检索本身解决的正是"是否同一知识点"。
2. 按 `score` 降序，最多 3 条。
3. `video_id` 必须有对应的可播放资源，否则不要返回该条。
4. **契约只保证数据结构稳定，不规定前端如何播放**（渲染方式由本仓库决定，见 §4）。

## 4. 视频呈现（本仓库侧决策，说明现状）

现状事实：本小程序为**个人主体**，当前服务类目「教育服务-教育信息展示」在官方类目表中明确**不支持教育视频播放/直播**。

**2026-09-25 更新（用户要求直接播放）**：已实现播放入口，并把它放在**服务端开关**后面：

| 开关 | 位置 | 行为 |
| --- | --- | --- |
| `VIDEO_PLAYBACK` | 云函数 `api` 环境变量，默认 `on` | `off` 时不向客户端下发 `file_id`，前端自动退回"只显示标题与时间点"的降级呈现；**改环境变量即刻生效，无需重新提审小程序** |
| `VIDEO_CLOUD_BASE` | 同上 | 云存储文件 ID 前缀（默认 `cloud://cloud1-d4gwsysje82cf604a.636c-...-1476352837`）；与实际不符时改环境变量即可，不用改代码 |

播放链路：`video_refs[].video_id` → 云函数拼成 `{VIDEO_CLOUD_BASE}/videos/{video_id}.mp4` 的 `file_id` → 前端 `pages/video/video` 用 `video` 组件 + `initial-time` 从片段起点播放（云文件 ID 由 `video` 组件原生支持）。

**风险仍在**：个人主体「教育服务-教育信息展示」在官方类目表中标注"不支持教育视频播放"，此功能能否过审须以实际提审结论为准。一旦被拒，把 `VIDEO_PLAYBACK` 置 `off` 即可立刻回到合规的降级呈现。契约侧仍要求：**不要在回答文本里承诺"点击即可播放"**（由前端卡片承担交互，模型不参与）。

## 5. 失败与降级（双方都必须实现）

| 情形 | 千问侧行为 | 云函数侧行为 |
| --- | --- | --- |
| 未命中课程知识 | 返回 `matched=false`，`answer` 可为空串 | 回落现有链路：16 篇知识库 + DeepSeek 回答 |
| 超时（>8s）、5xx、鉴权失败 | — | 回落现有链路，用户无感 |
| 响应体不合法（缺 `answer`、类型不符） | — | 视为失败，回落现有链路 |
| 命中但无视频 | `matched=true`，`video_refs=[]` | 正常展示文字回答 |

铁律：**不得出现 `matched=true` 而 `answer` 为空**。任何异常都应让云函数能干净降级。

## 6. 数据、隐私与教学资产

### 6.1 允许上传到千问侧语料范围

仅限**课程派生文本**：转写文本（`01_转写文本`）、PPT 提取（`02_PPT提取`）、习题讲稿、知识点索引摘要（`03_知识点索引`）。

### 6.2 上传前必须清洗

1. 剔除个人信息：手机号、邮箱、姓名学号、签到名单等。
2. 剔除与课程无关的行政内容。
3. 保留"视频ID / 片段起止时间"元数据（后续视频定位依赖它）。

### 6.3 教学资产的单一权威

`cloudfunctions/api/knowledge/*.md`（16 篇）与 `cloudfunctions/api/prompts/*.md`（2 篇）是**长期教学资产，以 Git 仓库为唯一权威**（C7 F6/F7）。

若上传到平台供检索使用，只能作为**派生的只读副本**：平台侧禁止直接编辑，任何修改都在仓库里完成、经用户审核后重新上传。

### 6.4 学生数据

1. 学生提问内容仅用于**本次回答**，不得用于模型训练，不得长期留存（平台条款需由用户确认）。
2. 禁止传输：学生姓名、学号、openid、真实对话原始记录。
3. **图片（2026-09-25 起）**：学生拍题的照片可以随请求传给服务侧用于**读题**，但必须满足——只用于本次回答；**不得落库、不得留存、不得用于训练**；服务侧读题完成后不得保留副本。
   - 数据接收方与既有链路相同（阿里云百炼的视觉模型），差别仅是请求会经服务侧中转
   - 前端必须提示学生"不要拍到姓名学号等个人信息"（已在 `pages/ai/ai.wxml` 落地）
   - 服务端可用 `AI_IMAGE=off` 紧急关停图片通道（成本或合规原因）
4. **题号不得作为检索依据**：题目编号（如 5-03）可能随作业册改版而变，检索与置顶一律依据**题干内容**，不得对题号做精确匹配或加权。

## 11. 责任分工与交付标准（千问侧做到什么程度）

### 11.1 三方分工

| 事项 | 千问侧 | 本仓库（Codex） | 用户 |
| --- | --- | --- | --- |
| 语料准备（转写 / PPT 提取 / 切片 / 向量化） | ● 负责 | 验收 | — |
| 检索与生成服务实现（测试环境调通） | ● 负责 | 审查 + 改造接入 | — |
| 平台侧配置（知识库、检索服务参数） | ● 负责并抄录留档 | 存档到 `docs/` | 确认 |

### 12.8 平台侧配置事实（2026-09-25 真机排查记录）

1. **云存储权限必须是「所有用户可读」。** 这是本次真机播放失败的唯一根因：权限当时是「仅创建者可读写」，而该配置**只对小程序端发起的请求生效**（控制台与服务端始终有全部权限），学生不是创建者 → 文件读不到 → `video` 组件加载失败（表现为进度 00:00、时长 00:00），**与地址、文件名、编码无关**。
   - 位置：云开发控制台 → 存储 → 权限
   - 生效时间：**1–3 分钟**；不需要重新部署云函数，也不需要重传文件
   - **下次新建环境或迁移环境时，第一件事就是确认这一项**
   - 安全边界：这意味着"拿到 fileID 即可读"，课程视频可接受，但不要在这个存储放需要保密的内容
2. **视频建议 faststart 布局。** 首批视频的 `moov` 在文件尾部（非 faststart），首帧需先取尾部索引，首播偏慢。第二批上传前建议无损转封装：
   `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`（不重新编码）
3. **云数据库集合 `knowledge_base`（2725 条）当前未被任何代码使用**：检索在千问侧 SCF 服务内用它自身的 `vectors.bin` 完成，仓库侧只调用该服务的 HTTPS 接口。保留或清理由用户决定；若保留，请注意它并非线上检索数据源。
4. **视频编码已确认可播**：首批文件为 `avc1`（H.264）+ `mp4a`（AAC），无需转码。
5. **排障经验**：播放页 `onError` 里保留了一次静默的 `wx.cloud.getTempFileURL` 自检（仅写 Console），用于区分"文件不可读（权限）"与"可读但播不动（编码/网络）"；面向学生的提示文案不含技术细节。
6. **隐私授权弹窗必须合规（2026-09-25 踩坑）**：微信要求"同意"必须由 `<button open-type="agreePrivacyAuthorization">` 触发，且 `wx.onNeedPrivacyAuthorization` 的回调必须写成 `resolve({ buttonId: 'agree-btn', event: 'agree' })`。用 `wx.showModal` 的"确定"冒充同意按钮时**微信不认可**，`wx.requirePrivacyAuthorize` 会直接走 `fail`，表现就是"点同意也没反应、相机起不来"。
   - 实现：`app.js` 注册 `onNeedPrivacyAuthorization` 后把 `resolve` 转交当前页面；`pages/ai` 渲染合规弹窗（同意按钮 `id="agree-btn"`）
   - 前提：小程序管理后台《用户隐私保护指引》**已配置且审核通过**，并**声明"摄像头"**（`chooseMedia` 拍照）。未声明时即使弹窗合规，接口仍会失败
   - 判别：`requirePrivacyAuthorize` 走 fail = 用户拒绝（或授权状态被记住）；`chooseMedia:fail api scope is not declared…` = 后台未声明
   - 全项目目前只有 `pages/ai` 使用隐私接口（`chooseMedia`），其余页面不涉及
7. **服务侧读题分支的已知限制（待千问修复）**：线上实现为 `if img and not question:`——**只要同时带了文字，图片就被完全忽略**，检索只用那行文字。真机表现为"拍了题又打了一行字 → 推送的视频不对"。
   - 本仓库已临时规避：带图时按"纯图片"调用（让服务侧读题），读不出来再用学生文字重试一次
   - **服务侧应改为**：只要请求带图就先读题（`vision_read`），再把"题干文字 + 学生文字"合并作为检索 query；这样两条信息都不浪费
   - 另建议：读题结果（题干文字）随响应回传，便于本仓库侧排查与埋点

你是一位大学《画法几何与工程制图》老师，学生叫你"同学"。你的价值是"教得会、带得动"，不是把知识复述一遍。

### 13.2 回答结构（硬性）

1. **先给结论或最关键的一步**（1–2 句）；
2. 再给必要的 1–2 句解释——**讲依据**（"这一步为什么这么做"），不堆零散步骤、不跳步；
3. 末尾一句引导，让学生接着想或试着做；
4. **总长 ≤150 字**（一屏内），宁可短；
5. **不得复述题目**：读题结果只用于检索；不要"根据题意…""这道题要求…"这类把题干重念一遍的开头。

### 13.3 内容铁律

- **禁用 LaTeX**（`$...$`、`\frac`、`\triangle`），用"三角形 ABC""∠ABC""⊥""∥"
- **不编造**标准号、数值、比例系数、画法步骤；不确定就明说"不确定，建议核对教材/课件"
- 涉及查表（标准件尺寸、公差数值、模数系列、轴承尺寸等）只教"怎么算、查哪页"，**不给表中数值**
- 只讲正确做法，**不列易错点、不强调错误**
- **不代写作业成品**；不直接判定学生答案对错，先请学生讲自己的思路

### 13.4 方法体系（讲步骤按这套，不跳步）

- 求点/交线/截交线/相贯线：**先找特殊点 → 再补中间点 → 依次连接 → 判可见性**
- 求交点：先看**积聚性**；无积聚性用辅助平面三步骤（含直线作辅助平面 → 求交线 → 求交点）
- 求实长与倾角：**直角三角形法**（实长、坐标差、投影长、倾角四要素必须对应同一投影面）
- 求距离/夹角：转化为**求线段实长 + 求垂足**（线面角用余角法，面面角用补角法）
- 可见性判断：永远回到"**哪个侧面可见**"
- 学生卡住时，先帮他把题拆成"**基本作图问题**"（做属于平面的投影面平行线、求一般位置线段实长、做平面的最大斜度线、求一般位置线面交点……）再逐个完成
- 点的投影是根基：学生连点都不清时，先把他拉回点的三面投影规律

### 13.5 视频：建议观看，不是答案

- 回答末尾**可以**用一句话提示"这段内容有讲解视频，可以看看"；
- **不要说"点击即可播放"**之类的交互承诺——播放入口由小程序卡片承担，且受平台合规限制（见 §4）；
- 视频只是建议：**宁可不提，也不要把回答写空**；
- 视频与知识点不同题时（题目未录制），也应只做"相关讲解"的建议，不得暗示"这就是你这道题的讲解"。
- 定位就是"**参考视频**"：只要**知识点相关**即可（用户 2026-09-25 裁决），不必与学生手上那道题完全对应。

### 13.6 与仓库既有资产的一致性

本规格与 `cloudfunctions/api/prompts/teacher_system_prompt.md`、`cloudfunctions/api/ai/prompt.js` 的 `METHOD_RULES` 同源。改写后，**主链路（服务侧）与降级链路（本地 DeepSeek + 16 篇知识库）应给出一致的教学口径**——学生不该因为服务是否可用而看到两种风格的老师。
