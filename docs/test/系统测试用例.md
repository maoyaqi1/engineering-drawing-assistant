## 1. 使用约定

用例编号格式为 `TC-<域>-<序号>`。每个用例通过“覆盖需求”字段关联一个或多个稳定需求编号；执行结果写入单独的测试报告。

优先级：

- `P0`：核心教学、权限、数据安全或主链阻断。
- `P1`：主要业务路径、跨端一致性或验收必需项。
- `P2`：边界、异常、空态和体验一致性。

验证方式：

- `STATIC`：代码、配置、文档静态核对。
- `OFFLINE`：项目现有只读脚本或离线内存库用例。
- `SIM`：微信开发者工具模拟器。
- `DEVICE`：手机或平板真机。
- `BROWSER`：教师网页或浏览器几何演示。
- `CLOUD`：云开发控制台、云函数日志和真实数据库读写。

## 2. 公共测试数据

严禁在测试文档或仓库中填写真实学生姓名、学号、openid、密码或 Token。

| 数据标识 | 含义 |
| --- | --- |
| `T_SUPER` | 超级管理员账号 |
| `T_A` / `T_B` | 两位普通教师账号及各自名册 |
| `C_ACTIVE` | `T_A` 负责的活动班级 |
| `C_ARCHIVED` | `C_ACTIVE` 的已停用版本 |
| `C_DEMO` | 标记 `is_demo=true` 的演示班 |
| `S_NO_PROFILE` | 已登录但资料未填齐的游客 |
| `S_GUEST` | 资料完整但未命中名册的游客 |
| `S_ACTIVE` | 名册命中且班级 active 的学生 |
| `S_ARCHIVED` | 名册命中但班级停用的学生 |
| `S_NO_CLASS` | 名册命中但未分班的学生 |
| `S_INTERNAL` | openid 命中 `INTERNAL_OPENIDS` 的测试账号 |
| `S_TEST` | `data_quality=test` 的测试账号 |

## 9. 覆盖与执行规则

需求覆盖检查：

```powershell
node scripts/test-case-coverage-check.cjs
```

执行规则：

1. 选定测试范围后，按用例编号逐条记录实际结果，不得只写“整体通过”。
2. `STATIC` 和 `OFFLINE` 通过不等于真机、浏览器或云端验证通过。
3. 云函数测试必须在部署后执行；教师网页测试必须在发布后执行。
4. 未执行、环境不足或被阻塞的用例标记为“未覆盖”，不得标记为通过。
5. 缺陷必须记录复现步骤、期望、实际、证据和严重程度。
6. 需求变化完成后，同步更新本用例文档及覆盖映射。
