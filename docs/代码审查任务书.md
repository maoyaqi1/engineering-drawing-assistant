## 五、审查重点（按优先级）

### A. 教师后台专项（最高优先级）

教师后台由两半组成：云端 `cloudfunctions/teacher/index.js`（业务与权限）＋网页 `teacher-web/`（呈现与调用）。两半都要审，不要只审前端或只审云函数。

#### A1. 权限模型与越权（最高）

1. 授权辅助函数为 `requireAuth(event)`（第 137 行）与 `requireSuper(event)`（第 143 行）。**逐个核对 36 个 action 的授权级别**，并判断级别是否与其业务风险匹配。
2. **破坏性 / 管理类 action 必须确认鉴权**，两类分开看：
   - **删除与清理类（执行后不可逆）**：`data.reset`（897）、`data.personPurge`（1300）、`data.emptyAccounts`（1219）、`data.legacyRoster`（1258）、`student.purge`（1459）。
   - **维护与账号类**：`data.personList`（1077）、`roster.backfill`（778）、`teacher.create` / `update` / `delete`（228 / 257 / 293）。
   重点看：是否有 `requireSuper`、是否有二次确认或不可逆提示、是否存在"先删关联数据再删主体"造成部分失败的中间态、`removeWhereIn`（1028）的分批删除是否可能删错范围、删除条件是否会因为空参数而退化为"全量删除"。
3. **普通教师的数据可见范围**：文档声称"云函数按 `owner_teacher_id` 强制校验，不靠前端隐藏"。请验证这句话在**每个**读接口里是否真的成立 —— 逐一看 `student.list`（654）、`student.detail`、`student.records`（1644）、`learning.list`、`ai.questions`、`note.add/delete`、`class.detail`、`class.candidates`、`class.syncMembers` 的查询条件里是否带上了调用者身份过滤，能否通过传入他人 `class_id`、`student_id`、`teacher_id` 或空参数读到别人的数据。
4. **前端可见性与后端鉴权的一致性**：`teacher-web/js/app.js` 中只有 `unrostered`（未入册学生）与 `teachers`（教师管理）标记了 `superOnly`（第 23、27 行），其余路由普通教师可见。请核对每个前端路由实际调用的 action 在服务端是否也做了同样的限制 —— 前端隐藏不算限制。
5. token 生命周期：`makeToken`（61）生成方式是否足够随机；`teacher_sessions` 的过期校验与失效路径；`logout` 是否真正删除会话；密码 `hashPassword`（48）与 `makeSalt`（57）是否使用了合适的算法与加盐方式；`ensureSuperAdmin`（93）首次初始化逻辑与默认口令来源（`TEACHER_USERNAME` / `TEACHER_PASSWORD` 环境变量）。

#### A2. 名册与权限联动（高）

6. `grantAiAccess`（565）与 `revokeAiAccess`（581）的触发时机：录入 / 批量导入 / 收编 / 改学号 / 移除学生时，`students` 名册与 `roster`（AI 白名单）是否始终一致；是否存在"人已移除但 roster 仍有权限"或"改了学号后旧学号仍能提问"的残留。
7. 判重键是否为**学号 + 姓名**（`rosterKey`，450）。若只按学号判重，不同学校学号重复会误判 —— 这是项目已知的坑，请确认实现。
8. `buildRosterRecord`（519）、`resolveClassForTeacher`（548）、`adoptStudent`（1609）中班级归属与 `owner_teacher_id` 的赋值是否有被伪造或空值绕过的可能。

#### A3. 数据库读写（高）

9. 集合与字段**以代码实际读写为准**，不要凭猜测建议增删字段。重点看：是否存在未做类型/范围校验的写入；是否存在缺少唯一性约束、可被重复写入的路径（重复导入、重复收编）。
10. `ai_messages` 结构不得更改 —— 教师端统计依赖它，请勿建议改字段。
11. 批量导入（`importStudents`，1718）与清理类操作，按 `docs/rules/coding.md` §57 要求：是否对导入数据做了类型与范围校验；是否可能执行导入内容中的脚本或表达式。

#### A4. 教师网页（高）

12. `teacher-web/js/api.js`：token 存放位置（内存 / localStorage / sessionStorage）与会话清理；收到 `UNAUTHORIZED` 时是否自动清会话并回登录页；错误提示是否会泄露服务端细节。
13. `teacher-web/js/app.js`：是否存在 `innerHTML` 拼接用户可控数据（学生姓名、学号、班级名、教师备注、AI 提问内容）导致的 XSS；分页 / 筛选 / 空数据状态是否有兜底（无数据时应显示"暂无数据"而不是报错）。
14. `teacher-web/js/config.js` 的网关地址是公开的 HTTPS 网关（会随 GitHub Pages 一起公开），请确认这里没有其他敏感配置。
15. 教师网页发布走公开预览仓库的 `main` 分支（GitHub Pages），与代码仓库的 `master` 是两条线 —— 涉及"是否已发布"的结论只能标注为未验证。

#### A5. 统计口径（中）

16. `dashboard`（307）中的指标（学生总数、今日活跃、点线面今日、AI 提问今日、名册人数、已注册/未注册、近 7 天趋势、班级概况、学情提醒）计算口径是否与页面文案一致；"学情提醒"是否为规则生成而非推测；时区与"今日"边界（`dayKey`，150）是否按 Asia/Shanghai 处理。

### B. 学生端与 AI 教师安全（高）

1. `cloudfunctions/api/index.js`：16 个 action 的入参校验是否完整；`ai.ask` 是否**在服务端**校验提问者在 `roster` 内，能否通过直接调用绕过前端限制。
2. AI 接口滥用面：刷接口消耗第三方 API 额度、单用户限流、Prompt 注入（学生输入能否改写系统指令）、图片通道（`pages/ai/ai.js` 中 `enableImage: false`）打开后的风险。
3. 敏感信息：全仓库确认不存在密钥字面量，只有 `process.env.XXX`。

### C. 几何正确性（高）

1. 投影与坐标转换函数（`worldToView`、`projectPointToView`、等轴测投影等）公式是否自洽，三视图是否由同一份点模型派生。
2. 浮点比较是否使用容差而非严格相等；写入几何状态前是否校验有限性（NaN / Infinity）。
3. 退化情形是否被建模：两点重合、三点共线、截平面与立体相切或不相交、圆环大小半径取极端值、参数滑杆边界值。
4. `section-geometry.js` 的求交与截面环生成逻辑；`basic-solid.js` 的曲面体参数网格精度与轮廓线生成。

### D. 状态与生命周期（中）

1. Canvas / 事件监听 / 计时器是否有明确所有者与释放路径；页面卸载后是否残留。
2. `setData` 频率与拖动过程中的重绘节流；是否在拖动中同步做重计算。

### E. 代码质量（低）

重复逻辑、命名一致性、散落的魔法数字与阈值（应按章程集中定义容差）。仅作建议，不要求整改。
