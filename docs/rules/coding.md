## 4. 工作流程

任何实现任务开始前必须阅读相关文件。

不得仅凭文件名推断模块行为。

修改前应简述架构、目标文件和受影响模块。

只实现当前请求范围内的功能。

不得借机进行无关格式化或重构。

工作树中的未知改动视为用户改动。

不得覆盖或回滚用户改动。

修改完成后必须执行与风险相称的验证。

交付说明必须列出修改文件、类或工厂、新增方法、设计决策、限制与后续建议。

若仓库状态与项目规格不一致，应以实际代码为事实来源并报告差异。

## 5. 推荐目录职责

以下 `js/*.js` 清单是本章程写于源码落盘前的网页版设想，**当前仓库中并不存在**。实际布局如下：

- `pages/`：小程序页面——`index/` 主画布与交互、`ai/` AI 教师、`roster/` 名单、`teacher/` 教师端、`ruler/` 尺规作图、`login/`、`register/`、`survey/`、`terms/`。
- `utils/`：与页面无关的共享模块（如 `geo.js` 尺规作图纯几何工具）。
- `cloudfunctions/api`、`cloudfunctions/teacher`：学生端、教师端云函数，彼此独立。
- `web/`、`web-release/`：网页版；`teacher-web/`：教师网页控制台。
- `docs/`：设计与方案文档；`images/`、`screen/`：素材与截图。

下列原则对上述任何布局都适用：

- 模块不得通过隐式全局变量通信。
- 模块之间优先传递数据模型或事件，不传递 DOM 查询结果。
- 循环依赖必须在引入前消除。
- 单一文件明显承担两个领域职责时，应先提出拆分方案。

## 40. 命名规范

类、构造器和工厂类型使用 `PascalCase`。

函数、变量和实例使用 `camelCase`。

常量使用 `UPPER_SNAKE_CASE`。

文件名使用现有项目风格；初始建议小写单数名。

布尔值使用 `is`、`has`、`can`、`should` 或明确动词前缀。

事件处理函数使用 `handleXxx`。

注册监听函数使用 `onXxx` 或 `addXxxListener`。

转换函数必须包含来源和目标。

不得使用 `data`、`temp`、`obj` 等含义不清的长期变量名。

短循环变量和明确数学推导中的 `p`、`n`、`t` 可接受。

领域名称优先采用准确英文，中文用于 UI 和解释注释。

## 41. 函数设计

函数应只有一个清晰职责。

函数名称应描述结果或动作。

避免布尔参数控制完全不同的行为。

超过三个相关参数时优先使用命名选项对象。

公共函数必须验证关键前置条件。

内部高频函数可在调用链已验证时省略重复检查。

副作用必须从名称或文档可见。

禁止隐式读取可变全局状态。


## 来源：AGENTS.md §42

## 42. 类与组合

优先组合而非深继承。

领域模型不得依赖渲染层对象。

可将 `renderObject` 作为适配器持有，但要明确所有权。

通用行为通过小型服务或策略组合。

禁止建立 Point、Line、Plane、Solid 的庞大万能基类。

只有真正稳定且共享的契约才抽象接口。


## 来源：AGENTS.md §43

## 43. 事件与数据流

领域变更应发出语义事件。

例如 `point:moved`、`plane:changed` 和 `section:updated`。

事件负载必须包含对象 ID 和必要的新状态。

不得把整个场景对象作为默认事件负载。

事件订阅必须可解除。

销毁模块时必须解除全部订阅。

避免事件 A 触发 B、B 又隐式触发 A 的循环。

批量更新应支持暂停通知或合并通知。

## 44. 错误处理

用户输入错误应在界面就近提示。

几何退化是正常领域状态，不应全部抛异常。

程序不变量被破坏时应快速失败并提供上下文。

不得用空 `catch` 吞掉错误。

控制台错误应包含模块和对象 ID。

生产交互不得因单个无效对象停止整个渲染循环。

恢复策略必须避免继续传播 NaN。

任何写入场景的位置、矩阵和顶点数据前都应保证数值有限。

## 45. 注释规范

注释解释原因、坐标约定和非显然算法。

不得逐行复述代码。

几何公式注释必须定义符号。

涉及论文、标准或算法来源时应注明名称和链接信息。

临时 TODO 必须写明缺失行为和触发条件。

禁止留下无负责人语义的“以后优化”。

复杂截交函数应说明输入空间、容差和退化返回值。

## 46. CSS 规范

主题颜色和尺寸使用 CSS 自定义属性。

轴色、投影面色和教学高亮色应集中定义。

组件状态使用类或数据属性，不使用大量内联样式。

禁止依赖脆弱的深层 DOM 选择器。

画布容器必须正确处理 `min-width: 0` 和 `min-height: 0`。

工具栏溢出必须可滚动或折叠。

打印样式只有明确需求时才实现。


## 来源：AGENTS.md §47

## 47. HTML 规范

使用语义化结构。

按钮必须使用 `<button>`，不得用无键盘行为的 `<div>` 模拟。

表单控件必须有 `<label>`。

三维画布和三视图区域应有可访问说明。

脚本加载顺序必须显式且稳定。

如果使用原生 ES modules，必须验证直接打开文件时的浏览器限制。

由于项目要求直接打开 `index.html`，不得未经验证依赖 `file://` 下受限模块行为。

## 48. 性能预算

普通交互目标帧率为 60 FPS。

高频指针事件应合并到渲染帧处理。

截交计算应与实际脏状态绑定。

不得每帧重建所有实体投影。

不得每帧重新创建所有标签 DOM。

大批量点线可考虑 InstancedMesh 或合并缓冲区。

优化必须保留对象级拾取或提供映射。

长期运行后对象数、材质数和纹理数不应持续增长。

可使用 `renderer.info` 辅助检查泄漏。

## 56. 兼容性

保持现代桌面浏览器兼容。

不得依赖未经降级说明的实验 API。

使用 Pointer Events 统一鼠标和触控时应处理 pointer capture。

画布节点或 Canvas 2D 能力不可用时应显示清晰提示，不得静默停在空白画布。

页面从 `file://` 打开时核心路径必须工作。

本地资源路径必须使用相对路径并注意大小写一致性。


## 来源：AGENTS.md §57

## 57. 安全与稳健性

用户输入不得通过 `innerHTML` 直接插入。

标签文本使用 `textContent`。

导入数据若未来实现，必须验证类型、范围和有限数值。

不得执行导入数据中的脚本或表达式。

外部资源失败不得让已加载教学功能整体崩溃。


## 来源：AGENTS.md §59

## 59. 变更范围控制

修复局部缺陷时优先局部修改。

需要架构调整时先描述问题、风险和渐进方案。

不得因个人偏好重命名全部模块。

不得在功能提交中混入全仓格式化。

不得重写已工作的算法，除非有可复现错误、明确需求或可验证收益。

替换算法时必须保留或扩充回归案例。
