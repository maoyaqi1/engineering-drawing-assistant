## 1. 总体原则

### 1.1 目标

1. **降低上下文成本**：让 `AGENTS.md` 只承载“每个 Agent、每个任务都成立”的规则和一个精确的路由表；专题规则只在任务命中时加载。
2. **不丢规则**：分层是“搬家 + 建索引 + 定加载协议”，不是删除、摘要或弱化规则。
3. **单一权威**：同一条规则只能有一个权威位置，其他位置只允许指针。迁移完成后不允许“两处各写一份、内容逐渐漂移”。
4. **安全前置**：授权门禁、冻结模块清单、禁止自行提交/推送、禁止写入密钥等安全条款永不外迁。
5. **按需可预测**：任何 Agent 都能从 `AGENTS.md` 的触发表判断“这个任务必须再读哪几个文件”，而不是靠记忆或猜测。

### 1.2 三层加载模型

| 层 | 文件 | 何时读取 | 承载内容 |
| --- | --- | --- | --- |
| 1 全局层 | `AGENTS.md` | 每次任务必读 | 产品边界、技术栈硬约束、文件分级、安全门禁、完成定义、规则索引与触发表 |
| 2 角色层 | `.agent/requirements.md`、`.agent/developer.md`、`.agent/tester.md` | 按当前角色读取 | 角色职责、必读材料、输出物模板、角色特有禁止项 |
| 3 专题层 | `docs/rules/*.md` | 按任务命中触发表读取 | 几何、教学应用、教师后台、云与数据库、测试、Git 发布、通用编码、Web 前端、项目事实 |

关键现实约束：Codex 会自动加载 `AGENTS.md`，但**不会自动加载** `.agent/*.md` 或 `docs/rules/*.md`。因此：

1. `AGENTS.md` 必须包含一张明确的专题文件索引与触发条件表。
2. 角色文件必须写明“本角色在什么任务下还要读哪些专题文件”。
3. 任何专题文件被移动、改名或删除时，必须同步更新 `AGENTS.md` 与角色文件中的指针。
4. 若触发表命中的专题文件不存在，Agent 必须停止并请求确认，不得凭记忆执行。

### 1.3 分类定义（A–I）

| 分类 | 定义 | 建议目标位置 |
| --- | --- | --- |
| A GLOBAL | 所有 Agent、所有任务都必须知道的规则 | `AGENTS.md` 保留 |
| B AGENT-COORDINATION | 多 Agent 协作、任务交接、角色边界 | `docs/rules/01-agent-coordination.md` + 角色文件 |
| C GEOMETRY | 画法几何、投影、几何计算、坐标、立体、截交、相贯 | `docs/rules/geometry/` |
| D TEACHING-APP | 学生端、教学交互、AI 教师、教学资产、教学呈现 | `docs/rules/02-teaching-app.md` |
| E TEACHER-BACKEND | 教师后台、教师端业务、学生管理、班级、课程、统计、权限界面 | `docs/rules/03-teacher-backend.md` |
| F CLOUD-DATABASE | 云函数、CloudBase、数据库、API、数据结构、权限服务端、部署接口 | `docs/rules/04-cloud-database.md` |

### 1.4 分类判定规则

1. **按正文判定，不按标题判定**：例如 §5 标题是“推荐目录职责”，但正文包含过期页面清单和跨模块架构原则，必须拆开看。
2. **一条规则一个主分类**：跨域时标注“多域依赖”，并指定“主分类 + 从属分类”，避免每个专题都复制一份。
3. **“必须保留在 AGENTS.md”有三种理由**：安全门禁、全局产品边界、专题路由所需。只要命中其中一种，就不能整节移走。
4. **混合条目不拆文字**：若一节同时包含全局部分和专业部分，本方案只标注拆分建议，不改变原文；迁移时再按“保留段 + 迁出段 + 交叉引用”处理。
5. **先建再删**：专题文件、索引、原章节到新位置的映射表全部就绪后，才允许从 `AGENTS.md` 删除已迁移正文。
6. **冲突不静默处理**：发现冲突先单列（见 §9），由用户裁决后再迁移。
7. **本方案不创建任何专题规则文件**：只规定它们的建议路径、来源章节、触发条件和边界。

### 1.5 迁移批次原则

1. 每一批只处理文档，不改业务代码，不碰数据库。
2. 每一批完成后必须做“规则保留检查”：原章节编号到新位置一一对应，不能有章节消失。
3. 每一批完成后必须做“引用检查”：所有指针指向存在的文件，所有被拆出的章节都有交叉引用。
4. `AGENTS.md` 的正文删除必须放在最后一批，且单独获得用户授权。
5. `.agent/*.md` 的去重与改写不在本轮范围，也不在本方案的自动执行范围内。

### 5.4 降级与例外

1. “普通小修改”可以不加载专题，但必须同时满足：不触及几何、教学、AI 教师、教师后台、云函数、数据库、权限、教学资产、Git 发布；改动文件属于 C7 的 A 级，或 B 级且已按 B 级要求说明范围。

3. 触发条件命中的专题文件不存在、路径失效或内容明显过期时，Agent 必须停止并请求确认，不得凭记忆执行。

5. 角色文件与专题文件冲突时，以 `AGENTS.md` 的优先级规则为准，并先报告冲突。

## 7. 绝对不能从 AGENTS.md 移走的清单

以下内容无论分层多深，都必须在 `AGENTS.md` 中保留可读正文，而不是只留一个“见某文件”的指针：

1. **章程效力、执行优先级与冲突处理**：用户要求优先；发现冲突不得静默选择；文档与代码不一致时以代码事实为准。
2. **产品定位与成功标准**：画法几何互动教学平台，不是 CAD；正确性、可解释性、教学反馈优先于功能数量。
3. **技术栈硬边界**：原生小程序、Canvas 2D、微信云开发、原生 HTML/CSS/JS；禁止 Three.js/WebGL、React/Vue/Angular/Electron、转译语法、客户端构建链、新 CDN 运行时依赖。
4. **目录路由索引**：至少保留路径到职责、稳定/冻结/探索状态的映射，以及专题文件触发条件。
5. **文件可修改性 A/B/C/D 四级表**：尤其 C 级冻结模块的两种允许情形与 D 级禁止改动、禁止提交范围。
6. **授权门禁**：触及冻结模块、数据库结构、教学资产、部署链路、权限模型时必须升级用户。
7. **开工前最小门禁**：先读相关代码；确认文件分级；确认改动范围；确认验收与回归；确认工作区是否有他人未提交改动。
8. **禁止自行提交与推送**：Agent 不得自行 `commit` 或 `push`，除非用户在该次任务中明确要求。
9. **禁止丢弃或回滚他人改动**：不得用 `git checkout --`、`git reset`、`stash` 等丢弃工作区内容；未知改动视为用户改动。
10. **敏感信息禁令**：不得把密钥、密码、Token 写入代码、文档、注释或 Git；只允许环境变量引用。
11. **无自动化测试的事实与四条回归底线**：不得用“测试已通过”指代不存在的自动化测试；任何改动后至少完成四条底线。
12. **交付摘要契约**：修改文件、新增类型、新增方法、设计决策、验证、已知限制、后续改进；不得只报“已完成”；不得把未验证写成已验证。
13. **几何与教学不变量摘要**：几何真值独立于渲染对象；投影与截面共享同一领域数据来源；每次改动必须保护已工作的教学能力；第一角投影不得无声改变。
14. **专题路由表本身**：文件路径、分类、触发条件、缺失时的停止规则；这是分层能否被实际执行的关键，不能外迁。

1. C1–C12 与 §1–§64 **不是两套互不相干的规则**：C1–C12 是协作与治理层，§1–§64 是技术实现层，两者通过 C3、C4、C7、C8、C9、C11、C12 与 §2、§3、§4、§5、§40–§47、§49–§55、§60、§62 大量交叉。

4. **单一权威检查**：同一规则不得在两个位置各写一份正文；重复位置只能是指针。
5. **加载演练**：至少模拟三类任务，列出各自应加载的文件集合，确认不会漏读：

6. **规模检查**：每批记录 `AGENTS.md` 的字节数与行数，目标区间见 §8；若超过 25KB，回查是否把应迁正文留在全局层。
7. **只读边界检查**：每批结束后执行 `git status --short` 与 `git diff --stat`，确认只动了该批授权的文档文件，未动业务代码、数据库、`.agent/*.md`（除非该批明确授权）。
