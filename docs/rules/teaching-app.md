## 34. UI 状态机

工具模式应通过显式状态机管理。

推荐状态包括选择、建点、建线、建面、建实体、截切和动画。

模式切换必须取消未完成的临时操作。

取消操作必须清理预览对象和监听状态。

工具按钮的视觉状态应来自同一模式状态。

不得让多个互斥工具同时激活。

键盘 Escape 应优先取消当前临时操作。


## 来源：AGENTS.md §35

## 35. 状态栏

状态栏显示当前坐标、选中对象、投影信息和相机状态。

坐标精度应统一配置。

未命中场景时不得显示陈旧坐标而不加说明。

对象信息应使用教学名称而不是内部类名。

异常和退化几何应提供简短可理解提示。

状态更新不得成为高频 DOM 性能瓶颈。


## 来源：AGENTS.md §36

## 36. 动画系统

动画应解释过程，而不只是让对象移动。

每个教学动画由可命名步骤组成。

步骤应声明起始状态、目标状态、持续时间和解释文本。

暂停后恢复必须连续。

改变速度不得改变最终几何状态。

拖动时间轴必须可确定地重建状态。

不得依赖从上一帧增量累加来实现可跳转时间轴。

推荐由标准化时间 `t` 计算状态。

分步模式必须停在有教学意义的关键帧。

动画结束后领域模型与画面必须一致。


## 来源：AGENTS.md §37

## 37. 教学呈现

新功能必须回答“学生能从画面中发现什么”。

重要对应关系应通过颜色、连线或同步高亮呈现。

颜色不能是唯一编码方式。

应配合线型、标记、标签或位置编码。

动画中一次只强调必要信息。

辅助构造应可隐藏但默认在教学步骤中可见。

数值结果应伴随几何含义。

不可用纯公式面板取代动态空间展示。


## 来源：AGENTS.md §38

## 38. 可访问性

所有工具按钮必须有文本或可访问名称。

键盘焦点必须可见。

颜色对比度应适合教室投影。

红绿轴除颜色外还必须有 X、Y 标签。

状态变化不应只靠短暂颜色闪烁表达。

滑块应显示当前值和单位。

触控目标应有合理尺寸。

响应式布局不得让核心控制不可达。


## 来源：AGENTS.md §39

## 39. 响应式布局

小程序端为上下布局：上方是空间视图，下方是三面投影展开区（当前约占 46% / 54%）。

网页版（`web/`、`web-release/`）可采用左右排列，窄屏时改为上下排列。

布局变化后必须按新尺寸重设画布 backing size 与设备像素比缩放，并重算布局单位长度。

二维投影视图也必须重算视口。

不得仅设置 CSS 尺寸而忽略 canvas backing size。

应考虑 `devicePixelRatio` 并设置合理上限。
