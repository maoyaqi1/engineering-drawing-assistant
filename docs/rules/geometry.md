## 6. 应用分层

应用分为领域模型、几何算法、渲染适配、交互控制和界面呈现五层。

领域模型保存教学对象的真实状态。

几何算法只接收数据并返回数据。

渲染适配把领域数据映射为屏幕绘制指令。

交互控制把指针输入转换为领域操作。

界面呈现显示工具、状态和说明。

几何算法不得直接操作 DOM。

界面模块不得直接改写几何真值或画布变换状态。

渲染对象不得成为几何真值的唯一存储位置。

投影视图不得从屏幕像素反推三维模型状态。

## 7. 场景层级

场景根节点下应建立命名分组。

推荐分组为 `coordinateRoot`、`projectionPlaneRoot`、`geometryRoot`、`helperRoot`、`sectionRoot` 和 `interactionRoot`。

教学对象的可见模型与辅助线应放入不同分组。

拾取对象必须能追溯到领域对象 ID。

临时预览不得混入持久模型集合。

场景节点名称用于调试，不得作为唯一身份。

身份应通过稳定 ID 和显式映射管理。

## 8. 坐标系

默认采用右手笛卡尔坐标系。

X 轴为红色。

Y 轴为绿色。

Z 轴为蓝色。

原点记为 O。

世界单位默认视为抽象教学单位，不擅自标注毫米。

三维点统一表示为 `(x, y, z)`。

禁止在同一算法中混用轴语义。

若历史代码采用不同的竖直轴，必须在适配边界集中转换。

不得在多个模块散布轴交换代码。

坐标转换函数必须在名称中标明来源和目标。

例如 `worldToFrontView`、`worldToTopView` 和 `worldToLeftView`。

## 9. 投影面定义

H 表示水平投影面。

V 表示正立投影面。

W 表示侧立投影面。

H、V、W 的数学定义必须集中声明。

建议用单位法向量和有符号偏移表示平面。

平面方程统一为 `n · p = d`。

法向量写入模型前必须归一化。

平面姿态不得同时由欧拉角和法向量独立保存。

应选择一个权威表示，其余数据按需派生。

H 默认浅蓝色。

V 默认浅绿色。

W 默认浅黄色。

投影面材质必须支持透明度调整。

锁定状态只限制交互，不应改变数学定义。


## 来源：AGENTS.md §10

## 10. 第一角投影

系统默认使用 ISO 第一角投影。

正视图、俯视图和左视图的展开关系必须在代码和教学文案中一致。

视图布局不能仅靠直觉放置。

投影符号约定应由一个配置对象集中定义。

每个三维点应通过同一投影管线生成三个二维点。

不得为点、线、平面和实体各自复制投影公式。

正视投影丢弃沿正视方向的深度分量。

俯视投影丢弃竖直分量，并按第一角展开约定定位。

左视投影丢弃侧向分量，并按第一角展开约定定位。

二维坐标必须与画布像素坐标分离。

模型视图坐标变换后，才应用缩放、平移和像素 Y 轴翻转。

缩放和平移不得改变几何投影结果。

## 11. 投影图元

投影结果应使用与三维对象相同的领域 ID。

正视、俯视和左视子图元应带有视图类型。

投影图元仅缓存派生数据。

领域对象变化时应标记相关投影为脏。

同一帧内多个变化应合并刷新。

可见轮廓使用实线。

不可见轮廓使用虚线。

中心线使用细点划线。

构造线使用低对比度细线。

投射对应线应可单独显示或隐藏。

线型规则必须集中定义，不得散落 CSS 和 JavaScript 魔法值。

## 12. 数学基础

纯几何函数不得修改输入参数。

返回对象的所有权必须清晰。

频繁路径允许使用调用方提供的输出向量以减少分配。

此类函数必须以 `out` 参数或注释明确说明。

向量比较不得使用严格浮点相等。

所有容差应来自共享数值策略。

推荐基础绝对容差 `EPSILON = 1e-8`。

屏幕合并与教学显示可使用更大的独立容差。

容差必须结合模型尺度。

推荐有效容差为 `max(EPSILON, scale * relativeEpsilon)`。

禁止用任意 `toFixed` 结果参与几何判断。

显示舍入只能发生在 UI 边界。

角度内部统一使用弧度。

界面可显示度数。

角度转换必须通过命名函数完成。

## 13. 点模型

点必须拥有稳定 ID、三维坐标、标签和可见状态。

标签默认按 A、B、C 顺序生成，但不得依赖标签作为 ID。

正视、俯视和侧视标签应由统一规则派生。

拖动点时必须即时更新坐标显示。

拖动约束应显式指定工作平面或轴。

禁止使用相机朝向变化导致不可预测的自由拖动。

坐标输入必须验证有限数值。

删除点前必须处理依赖它的线和平面。

依赖策略应是阻止、级联或失效标记中的一种，并在 UI 中说明。


## 来源：AGENTS.md §14

## 14. 线模型

线由两个不同的点定义。

零长度线必须拒绝创建或标记为无效。

线的方向为归一化的端点差向量。

真长来自三维端点距离。

投影长度来自对应二维投影点距离。

倾角应相对于明确命名的投影面计算。

夹角计算前应钳制点积到 `[-1, 1]`。

线型分类必须基于方向与投影面法向量的关系。

分类判断必须使用容差。

同一条线只能有一个权威端点集合。

改变端点后所有度量必须重新派生。

## 15. 平面模型

三点定平面时必须检查三点不共线。

平面模型推荐保存单位法向量 `normal` 和常数 `d`。

若需要有限显示边界，应与无限数学平面分开表示。

显示平面的尺寸不应影响求交结果。

平面旋转必须围绕明确的枢轴和轴。

平面平移应更新 `d`，并保持法向量不变。

通过姿态控件改变法向量后必须重新归一化。

平面迹线是平面与 H、V、W 的交线。

平行或重合情形必须返回明确状态。

不得用超大线段假装所有迹线都有有限端点。

## 16. 实体领域模型

支持长方体、六棱柱、三棱锥、圆柱、圆锥和球。

实体模型必须保存类型、变换、参数和稳定 ID。

实体局部几何与世界变换必须分离。

移动只改变位置。

旋转只改变姿态。

缩放策略必须明确是均匀还是非均匀。

负缩放默认禁止。

实体参数必须有合理下限。

多面体实体应提供顶点、边和面的拓扑。

曲面实体应提供解析参数，而不是只暴露三角网格。

渲染细分等级不得决定数学求交精度。


## 来源：AGENTS.md §17

## 17. 显示模式

实体支持实体、线框、透明和仅边线模式。

显示模式是渲染状态，不应改变领域几何。

不同实体应尽可能共享不可变材质模板。

对象级透明度不能通过克隆大量相同材质失控增长。

切换模式时必须清理不再使用的对象级资源。

边线颜色和宽度应满足课堂投影环境的对比度要求。

## 18. 截平面模型

截平面是独立领域对象。

它必须拥有法向量、偏移、显示尺寸、锁定和可见状态。

数学平面为无限平面。

显示网格只是操作手柄和视觉提示。

偏移沿单位法向量定义。

角度控件改变姿态，不得偷偷改变偏移。

平移控件的工作空间必须清晰。

截平面变化必须触发当前目标实体的截交更新。

连续拖动期间允许节流，但松手后必须精确刷新。

## 19. 多面体截交算法

多面体截交以拓扑边与无限截平面的交点为基础。

对每条边端点计算有符号距离 `s = n · p - d`。

若两端距离异号，则边与平面有唯一内部交点。

交点参数为 `t = s0 / (s0 - s1)`。

交点为 `p0 + t * (p1 - p0)`。

若端点距离在容差内为零，该端点属于截面。

若整条边共面，必须按共面边策略处理。

不得无条件把共面边的两个端点重复加入。

所有候选点必须按空间容差去重。

少于三个唯一点时不存在面状截面。

三个或更多点应投影到截平面的二维基底后排序。

排序不能直接使用世界 XY 平面。

应构造与法向量正交的稳定基向量 `u` 和 `v`。

基向量选择应避开与法向量近平行的参考轴。

以截点质心为排序中心。

按 `atan2(dot(q,v), dot(q,u))` 排序。

排序后应检查相邻重复点和零长度边。

凸多面体截面通常为单一凸多边形。

未来支持凹多面体时不得沿用单环假设。

## 20. 多面体退化情形

截平面完全位于实体外部时返回空结果。

截平面与单个顶点相切时返回点接触状态。

截平面沿一条边相切时返回线接触状态。

截平面与一个面共面时返回共面面状态。

这些状态不得伪装成普通截面多边形。

UI 应能以适当方式解释退化结果。

算法返回值应包含 `kind`、`points` 和诊断信息。

推荐 `kind` 值为 `none`、`point`、`segment`、`polygon` 和 `coplanarFace`。

## 21. 圆柱截交

圆柱截交优先使用局部坐标中的解析或半解析方法。

不得仅依赖当前渲染网格的三角形切片。

平面垂直圆柱轴时截线为圆。

一般斜截且不越过端盖时截线为椭圆。

与有限圆柱求交时必须考虑上下端盖和侧面边界。

采样曲线必须按参数连续排序。

采样密度应由视觉误差或可配置教学质量决定。

拖动时可使用较低预览质量。

交互结束后必须恢复最终质量。

解析特殊情形应保留语义，便于显示“圆”或“椭圆”。


## 来源：AGENTS.md §22

## 22. 圆锥截交

圆锥使用有限单叶圆锥模型，除非功能明确要求双叶延拓。

截交必须考虑顶点、底面和有限高度。

截线可能为圆、椭圆、抛物线式开放片段、双曲线式片段或退化线。

有限实体上的结果可能被边界截断。

教学标签不得仅凭外观猜测圆锥曲线类型。

分类应根据平面法向量与圆锥半顶角关系完成。

接近分类边界时使用容差并显示“临界”状态。

曲线采样不得跨越不连续分支强行连线。


## 来源：AGENTS.md §23

## 23. 球截交

球与平面的截线为空、点或圆。

设球心到平面的有符号距离为 `h`。

若 `abs(h) > radius + tolerance`，结果为空。

若 `abs(abs(h) - radius) <= tolerance`，结果为切点。

否则截圆半径为 `sqrt(radius² - h²)`。

截圆圆心为球心沿平面法向量的垂足。

显示采样点应位于截平面基底中。

不得通过三角网格边交点拟合球截圆作为最终结果。


## 来源：AGENTS.md §24

## 24. 截面输出模型

截交算法输出不得直接是渲染对象或屏幕坐标。

输出应包含截面类型、三维点、闭合状态、曲线语义和来源实体 ID。

多边形可包含有序顶点与边来源映射。

曲线可包含参数区间和采样点。

输出应能直接驱动三维高亮与三视图投影。

同一截面数据必须同时作为两个视图系统的来源。

不得在正投影视图中重新计算另一套截交。


## 来源：AGENTS.md §25

## 25. 截面渲染

截面轮廓应明显区别于实体边线。

截面填充应半透明并避免严重 Z-fighting。

优先使用合理的渲染层、polygon offset 或轻微法向偏置。

偏置只属于渲染层，不得写回几何数据。

闭合多边形三角化应在截平面二维坐标中完成。

凹多边形不得使用简单扇形三角化。

曲线轮廓必须处理闭合端点重复问题。

更新动态 BufferGeometry 时应复用缓冲区或正确释放旧资源。


## 来源：AGENTS.md §26

## 26. 相贯线边界

实体相贯属于未来独立模块。

截面算法不得硬编码第二个实体。

相贯线算法必须保留构造过程所需的中间数据。

只显示最终曲线不足以满足教学目标。

未来实现应支持母线法、辅助平面法或辅助球面法等教学步骤。

当前提交不得以粗糙布尔库替代可解释过程并称为完成。


## 来源：AGENTS.md §27

## 27. 变换规则

领域对象应保存局部几何和对象变换。

求交可将截平面变换到实体局部空间，或将实体几何变换到世界空间。

同一算法必须坚持一种空间。

变量名称应标明 `local`、`world`、`view` 或 `screen`。

法向量变换必须使用逆转置矩阵。

存在非均匀缩放时不得用普通方向变换替代。

矩阵求逆失败必须显式处理。

对象变换更新后应调用必要的世界矩阵更新。

不得依赖渲染循环碰巧更新矩阵后才获得正确结果。


## 来源：AGENTS.md §28

## 28. 渲染资源所有权

当前渲染层是 Canvas 2D：绘制对象是每帧重建的路径、屏幕点与样式字符串，没有需要在代码中显式释放的 GPU 资源；本节规定的是画布、上下文与缓存的持有边界。

画布节点与 2D 上下文由页面实例持有，`initializeCanvas()` 是唯一创建入口。

`onUnload()` 必须解绑画布、上下文与缓存（`sectionSolidCache`、`sectionResultCache`），不留悬空引用。

交互状态（`canvasDragging` 等）属于生命周期资源，拖动结束与离开页面时必须复位。

绘制函数不得把上下文、画布或缓存挂到模块级变量；跨调用共享的状态只能来自页面实例。

单次绘制内产生的临时数组、路径与对象应随绘制结束丢弃，不得无界累积。

若将来引入 WebGL 或离屏画布，必须重新定义“谁创建、谁持有、何时释放”的资源所有权，不得沿用本节。

## 29. 几何复用与缓存

几何真值只保存在领域数据中（`this.data` 的点、直线、平面与立体参数）；绘制层不得另存一份真值。

绘制层只读领域数据；高亮、选中、线型等仅作为绘制参数传入，不得写回。

复用计算结果必须经过缓存，缓存键必须包含影响结果的全部参数（截面缓存的 `resultKey`）。

缓存必须有明确失效点：参数变化、模式切换与会话结束都必须失效或清空。

缓存不得跨会话、跨模式残留。

需要独立修改的数据不得与其它对象共享同一可变引用；应先复制再改（如展开 `{ ...point }`）。

基本立体与截交结果分别由 `basic-solid.js`、`section-geometry.js` 计算，绘制层只调用、不重算。

为复用而牺牲可读性或正确性不被接受。


## 来源：AGENTS.md §30

## 30. 重绘调度与性能

只有一个重绘入口 `scheduleCanvasDraw()`；子模块不得各自创建绘制循环。

重复的重绘请求必须合并到同一帧，用调度标志（`_drawScheduled`）去重。

优先使用画布自带 `requestAnimationFrame`，不可用时退化为 16ms 定时。

静态状态按需重绘，不保留常驻动画循环。

拖动过程中只更新内存值并请求重绘，`setData` 只在拖动结束时提交一次。

每帧不得重复执行节点查询或布局量算；`createSelectorQuery` 只用于初始化。

设置画布 `width`/`height` 会重置变换矩阵，之后必须重新应用设备像素比缩放（`context.scale`）。

设备像素比缩放必须设上限（当前为 3），避免低端设备过度绘制。

屏幕坐标一律使用逻辑像素；命中阈值等交互常量不得随像素比变化。

优化前必须先确认热点；不得以牺牲几何正确性换取不可测量的微优化。


## 来源：AGENTS.md §31

## 31. 视图与投影布局

空间视图使用固定斜轴测基底（X 向左下、Y 向右下、Z 向上），**不提供自由旋转**；不得为“可旋转”引入相机系统。

三面投影使用固定正投影：正视 (x, z)、俯视 (x, -y)、侧视 (-y, z)，展开关系必须符合第一角约定（§10）。

布局由 `getLayout()` 唯一决定（上方空间视图约占 46%，下方为三面投影展开区）；绘制函数不得自行推导位置或比例。

比例尺统一由布局单位长度决定；空间视图与三个投影视图必须共用同一套坐标映射（`projectIsometric` 与 `worldToView`）。

空间点与其三个投影点必须来自同一几何真值，并使用同一映射。

重置必须恢复完整布局与默认教学状态（`handleReset()`）。

不得用极端缩放或裁剪掩盖尺度设计问题；教学坐标范围 0..8 的对象必须完整落在可视区域内。


## 来源：AGENTS.md §32

## 32. 拾取与选择

拾取判定在屏幕（逻辑像素）坐标中进行，命中阈值统一（当前 30）。

只有点、直线、平面三种模式提供拖动入口；截面模式与立体模式不得触达拖动路径。

可拾取对象限定为当前模式的控制点：点模式取点，直线模式取两个端点，平面模式取三个顶点。

拾取候选限定在三面投影视图内；空间视图不参与拾取。

命中判定必须使用当前布局量算出的屏幕位置，不得使用过期尺寸或缓存坐标。

命中顺序必须确定（按 a → b → c 依次判定），不得依赖不确定的遍历顺序。

同一时刻只允许一个拖动主体（`draggingProjection` / `draggingLineProjection` / `draggingPlaneProjection` 三选一），开始新拖动前必须清除旧状态。

选中与拖动状态只有一份权威存储（页面 data 或实例属性），绘制层只读。

拖动结束、切换模式或重置后必须清除选中与拖动引用。


## 来源：AGENTS.md §33

## 33. 拖动交互

拖动只发生在三面投影视图内；空间视图不参与拖动（与“直接拖三维对象”是两种交互）。

拖动开始时必须记录被拖对象、被拖的键与视图类型（如 `draggingPlaneProjection = { pointKey, viewType }`）。

拖动只修改该视图可见的两个坐标，第三个坐标保持原值：正视改 x/z，俯视改 x/y，侧视改 y/z。

屏幕位移必须换算为模型值（`screenToModel`），不得把像素增量直接累加进世界坐标。

换算结果必须取整并钳制在教学模型范围（0..8）内——模型坐标是整数语义。

拖动期间必须锁定页面滚动（`canvasDragging` 驱动滚动容器），否则手势会被滚动容器吞掉。

语义校验必须在写回前完成：平面三点共线时放弃本次更新（`isPlaneNonCollinear`）。

拖动使对象不再符合当前预设类型时，类型必须回退为一般情形（`general`），且不得与预设冲突。

拖动结束必须清理全部拖动状态并恢复滚动。

拖动应形成一次语义操作；若将来实现历史系统，应可直接接入撤销。
