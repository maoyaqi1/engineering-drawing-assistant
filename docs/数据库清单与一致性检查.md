# 云数据库清单与一致性检查（2026-09-13）

> 本文由代码逐字段核对得出（不依赖任何云端数据）；真实数据的体检报告见 §5 的导出与 `scripts/data-audit.js`。
> 权威判据：`cloudfunctions/api`（学生端）、`cloudfunctions/teacher`（教师端）的实际读写代码。

## 1. 集合清单（16 个）

## 2. 三条权威链（不一致都出在这三处）

### 2.1 身份三源：`users`（学生自报） ↔ `students`（教师名册） ↔ `roster`（AI 白名单）

- 权威：名册与白名单由教师端写入；`users` 是学生自报。
- 放行键：**学号 + 姓名**（`resolveAccess`，学校不参与）。
- 常见不一致：白名单孤儿（有白名单、无名册）、名册有但白名单没有（拿不到 AI 权限）、`roster` 里只有学号没姓名的 `legacy_import` 行（**不参与放行**）、同 openid 多条账号（登录自愈会收敛）。

### 2.2 班级双轨：`students.class_id`（权威） vs `students.class_name`（快照）

- 班级成员数、班级详情列表一律按 `class_id`；学生页展示的是 `class_name` 文本。
- 解析不到班级实体时，代码会写 `class_id:''` 但**保留班级名文本**（`resolveClassForTeacher` 第 4 条分支）。
- 于是出现"名册写着某班、班级成员里没有"（2026-09-13 实测：教师组按 `class_id` 只有 3 人，而名册里写着"教师组"的有 5 条——另外 2 条 `class_id` 为空，即 `030101` 与 `20260303010120`）。
- 收敛手段：班级详情页「从名册并入」（`class.syncMembers`）；跨教师归属的学生需先改归属（`NOT_IN_SCOPE`）。

### 2.3 会话有效性：`is_valid` 与统计口径

- `session.start` 先写 `is_valid:false`；`session.end` 才按 `duration ≥ 60s 或 交互 ≥ 3 次` 置真。
- 学生端"有效学习次数"与教师端学生详情**只数 `is_valid:true`**；而驾驶舱的活跃/趋势/点线面次数**只按 `created_at` 过滤，没过滤 `is_valid`**（注释与实际不一致）。
- 后果：驾驶舱数字偏大，且与其它页面对不上；App 被切掉时留下的会话永远 `is_valid:false`。

## 3. 已知风险清单（按优先级）

1. **无数据库级唯一索引**：`users`(openid)、`roster`(学号+姓名)、`survey_responses`(user_id+survey_id)、`classes`(owner+name+school) 全靠查询判重，并发下可能重复。
2. **快照字段会漂移**：`students.class_name`、`learning_records.student_id/student_name`、`users.valid_session_count` 都是写入时快照，改学号/改名/删会话后不会自动回填。
3. **遗留数据**：`roster` 无姓名行（`legacy_import`）、`teacher_classes` 历史行、`users.nickname/avatar`、`ai_messages.model/token`（写入时未落库）。
4. **数据维护工具会真删数据**：`data.reset`（白名单含 `learning_sessions`/`learning_records`）、`data.personPurge`、`data.emptyAccounts`、`data.legacyRoster`；通过 `maintenance_logs` 可追溯。
5. **集合规模上限**：多处 `limit(1000)`/`fetchAll` 分页假设数据量不大，超过后统计会悄悄截断。

## 4. 与鉴权改造的关系

学生端 AI 放行只依赖 `users`（自报）+ `roster`（教师写入），**不依赖** `students`/`classes`；因此名册/班级的错误不会影响学生能否提问，只会影响教师端的呈现与统计。详见 `docs/用户与鉴权模型.md`。

## 5. 真实数据体检：导出 + 一条命令

1. 云开发控制台 → 数据库 → 逐个集合「导出」（JSON），把文件按集合名保存到一个**仓库之外**的目录，例如 `C:\Users\myq\db-export\`：
   `users.json`、`students.json`、`classes.json`、`roster.json`、`learning_sessions.json`、`learning_records.json`、`ai_conversations.json`、`ai_messages.json`、`survey_invites.json`、`survey_responses.json`、`teachers.json`、`teacher_notes.json`、`maintenance_logs.json`（没有数据的集合可跳过）。
   > 也可以导成一个 `all.json`，形如 `{ "users": [...], "students": [...] }`。
2. 运行：
   ```powershell
   node scripts/data-audit.js C:\Users\myq\db-export --out C:\Users\myq\db-export\report.txt
   ```
   它会输出/写出：集合条数与时间跨度、账号重复、白名单/名册/账号三源差异、班级双轨差额（逐班列出"名册里 N 条、实际成员 M 条"）、会话有效性分布与僵尸会话、事件快照漂移、问卷与清理留痕。
3. **报告含真实姓名与学号，不要放进仓库、不要提交**（工具默认只打印到终端）。

> 说明：本环境无法直连微信云数据库，真实数据只能靠导出后本地分析。
